The rule (spec2 Part 2): one interval I per (node, neighbor), I = I_min at start; at send `applied = I * (1 + jf*(2u-1))` and the next poll is provisionally `sent + applied`; at an answered resolution `I <- min(I*m, I_max)` if the reply was EMPTY and `I <- I_min` otherwise, and the next poll becomes `max(sent + I_new*(1 + jf*(2u-1)), now)` with the same u; at a timed-out resolution I is unchanged. EMPTY is evidence/11's `rx_no_new`: every seq 1..hi[o] of every origin o in the reply is already held by the polling node at that instant, and a reply with `hi == {}` counts as EMPTY.

## Headline: gain at equal polls, and polls saved at equal delay

`gain = 1 - delay(rule) / delay_frontier(polls_sent(rule))`, the frontier being the piecewise-linear log(delay) over log(polls_sent) through the four SIMULATED fixed arms of the same cell. Positive = faster than a fixed interval that costs the same number of polls. `save = 1 - polls_sent(rule) / polls_frontier(delay(rule))` is the same statement read the other way. 95 % intervals: 2000-resample bootstrap over the 20 seeds, `default_rng(20261117)`, the frontier and the rule recomputed from the same resampled seeds in every resample. A resample that puts the rule outside the four fixed arms' range yields no value, so an interval that rests on fewer than all 2000 resamples says so, and below half of them no interval is printed.

## Assumptions and deviations from spec2

1. **Bytes use the same `REP_B[p]` for every rule**, as spec2 states: the mean reply size is taken not to depend on the rule. `REP_B` exists for p 0 / 0.2 / 0.4 only, so the p 0.5 / 0.6 cells have no byte column, which is why the headline is stated in polls_sent and not in bytes.
2. **The bootstrap's unit is the seed, and each seed's value is the mean over its 5 replicates.** spec.md's B1 averages the replicates after pooling the seeds; for sums the two orders agree exactly, for the ratios (delay, cens4, EMPTY share) they differ in the last digits. The point estimates in the tables are pooled over all 100 (seed, replicate) runs, as spec.md pools them; only the bootstrap uses the per-seed replicate mean, because a bootstrap needs one value per unit.
3. **The EMPTY share of a measured cell is the published `rx_no_new / state_rx`** of evidence/11|12 `cells.csv`, not something this script recomputed: the logged `state_rx` lines carry no emptiness field, and the simulated figure comes from the engine's own store at the serve instant. The two are the same definition but not the same code path, so the measured EMPTY column is weaker evidence than the other measured columns.
4. **The tick-lag stream seed is the same for all 11 rules** at one (p, seed, replicate). Only the seed is shared: the rule path draws a lag at send and again when a resolution moves the due time, so it consumes 1.7 to 2.2 draws per poll against 1.3 to 1.4 for the fixed and table paths (measured in review), and the lag values differ from the first interval change on. What is paired across rules is the exogenous input (outages, creation times, agent start) and the jitter stream seed. The lag is at most 100 ms against intervals of 500 ms and more.
5. **`short` and `wait` take the policy table of the donor's own family** (`s6short`/`s6wait` for the s6 donor, `s5short`/`s5wait` for the s5 donor), as spec2 says. The two families' tables happen to be identical.
6. **No tuning.** The five variants listed in spec2 are the only rules run. Their numbers are reported as they came out.
7. **The RNG stream usage of the two code paths** (spec2 Part 2 asks for this to be said out loud). (a) The choices path draws `state_poll_interval:{seed}:{node}` once per poll to pick its interval; the rule path does not, because the rule has no choice to make. That stream is a separate `random.Random` instance from the jitter stream, so leaving it undrawn changes no jitter value, and no dummy draw was added. (b) The rule path draws its tick lag at SEND, where the choices path draws it, and the resolution re-arms the timer only when the recomputed due instant differs from the provisional one; the policy-table path instead defers the draw to the due instant (validate.md deviation 8). The two paths differ on purpose: each mirrors the path it has to stay bit-identical to. (c) With m = 1 and I_min = I_max the rule's due instant never differs, so the rule path consumes the single shared tick-lag stream in exactly the order the fixed arm does -- which is what the identity test above measures, in Mode B as well as Mode A.
8. **The identity test is exact on every event field but one.** `state.consecutive_poll_timeouts` of a `state_poll` decision differs: the choices path never maintains the counter and logs 0, the rule path maintains it when the NEWEST poll resolves (the source also folds older unanswered polls into it after a 1 s grace, engine.py `_PollReplies._expire`; the replay does not, so under the two sub-2 s variants the logged value is lower than the source's would be). It is a logged diagnostic that no metric, pass line or scheduling decision reads; every poll time, interval, reply, store time and cell metric is identical. Reported rather than silently normalised away.
   What the identity test does and does not show: with m = 1 the due time never moves at a resolution, so the test covers the EMPTY computation, the resolution bookkeeping and the reuse of the send-time jitter draw, but not the grow / cap arithmetic or the re-arm branch every real variant takes. Those were checked in review by an independent model of one (node, neighbor) pair: 2134 polls and 1932 resolutions over the five variants, 0 differences (review2-rule/mysim.py, not part of this directory).
9. **"Outside the frontier" is applied per axis.** spec2 says a variant outside the range of the four fixed arms gets no gain, without naming an axis. `gain` interpolates over `polls_sent` and `save` over `delay`, so a rule can be inside one and outside the other; each reading is suppressed on its own axis. In this run only T136c is outside, and only on delay (it is slower than the slowest fixed arm).
10. **A bootstrap interval resting on fewer than half the resamples is not printed.** spec2 does not say what to do when a resample puts the rule outside the frontier. The count of resamples an interval does rest on is printed whenever it is not all 2000 of them, so a conditional interval cannot be mistaken for an unconditional one.

### What the new rule makes observable that the logs never showed

facts-timers.md §9 lists two source branches as UNCONFIRMED because no logged run could reach them: `clamped == true` reschedules (0 of 37 423) and the `POLL_REPLY_GRACE_S` / `expired_timeouts` bookkeeping. Both need a poll interval below the 2 s interest lifetime, which T05 and T136 have. Under those two variants the replay therefore runs source paths that no measurement in this store validates: the provisional send-time timer firing before its poll resolves (engine.py:478), a poll that is never resolved because a newer one has been sent (engine.py:503), and the clamp at engine.py:522. Their numbers rest on reading the source, not on a logged comparison.
