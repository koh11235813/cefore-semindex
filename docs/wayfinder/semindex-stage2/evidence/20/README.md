# evidence/20: 物差しの seed の上で、固定の腕 3 つと決まり 2 つを実機で測った（2026-11-22）

3 つの決め方（後から分かった正解で調整した gemma-4-E2B、ログから学ぶ ML、式の決まり）を比べる段取りの、最初の実機の一手。物差しに使う seed 121〜160 の上で、固定の間隔の腕 3 つ（3.695・6.0・10.043 秒）と、時間切れで最短へ戻す決まり T37r、そして `fpin.py` が 1 つに固定した式 F を回した。合否の線となぞり直しの予測は、run の前に `spec.md` と `predict.txt` に置いた。チケットは `tickets/07-baseline-heldout.md`。

| 段 | 設定 |
|---|---|
| `s10b3p695` | 固定 3.695 秒、ゆらぎ 0.1 |
| `s10b6p0` | 固定 6.0 秒、ゆらぎ 0.1 |
| `s10b10p043` | 固定 10.043 秒、ゆらぎ 0.1 |
| `s10t37r` | 決まり T37r: i_min 3.695、伸び率 2、i_max 10.043、時間切れで戻す |
| `s10f` | 固定した F: i_min 3.695、伸び率 1.5、i_max 10.043、時間切れで戻す |

## 先に結論

- **なぞり直しは、p 0.2 のこのマスでも実機を言い当てた。** 5 段の遅れと状態確認の数、合わせて 10 個が全部 ±6 % の帯に入った。読みは「predicted」。当たって当然の 3 個を除いた 7 個も、7 個とも帯の中。6.0 秒の腕、T37r、F は、このマスでは実機の数が 1 つも無かった。それが付いた。
- **固定した F の得は +4.90 %（区間 +0.55〜+9.21）で、読みは「seen」。** 予測は +7.80 %（+3.95〜+11.76）の「seen」だったので、言葉は予測どおり。ただし点の値は予測より小さく、**T37r の +7.18 % より低い**。
- **F と T37r の差は見分けられなかった。** F − T37r は -2.28 ポイント（-6.10〜+1.50）で、読みは「not seen」。なぞり直しの予測は +0.72 ポイントだったので、**点の値は予測と向きが逆**。区間は 0 をまたぐので、この段は 2 つの決まりのどちらが線の上で勝っているかを言えていない。`fpin.txt` の +11.1 は、腕 7 つの線の上で、F を選んだ 20 seed の中で測った値で、物差しの seed には引き継がれなかった。`spec.md` が run の前に「あれは推定値ではない」と書いたとおりになった。
- **そのまま比べると、F は T37r に対して遅れが 4.82 % 短く（-8.75〜-0.53）、状態確認が 9.37 % 多い（+8.39〜+10.31）。** どちらの区間も 0 をまたがない。なぞり直しの予測は -7.91 % と +9.81 %。
- 200 本は全部 DONE で有効、印は 0。判断の間隔も 5 段とも設定の値だけ。

## 2 つの採点

`spec.md` が run より先に決めたもの。見出しの採点は、作られる予定の時刻が t0+72 秒までのレコードだけを数える。全レコードの採点は、これまでの段と同じ数え方。言葉は見出しの採点で読み、全レコードの値は横に置く。状態確認の数は、どちらの採点でも窓の全体（`[t0+10 秒, t0+130 秒]`）で数える。`w0` では 240 件が全部 t0+71 秒までに作られる予定なので、2 つの採点は同じレコードを選ぶ。実際そうなったかは `results.md` の測った列で、200 本とも 240 件・240 件だった。

## 読み

- 物差しの seed の上に、2 つの式の決まりの実測の基準が置けた。チケット 12 が 3 つの決め方を比べるとき、L と M はこの数を相手にする。
- この段は、F を T37r より上に置く理由を出していない。点の値では F のほうが低く、差の区間は 0 をまたぐ。**式の側をどちらにするかは、開いたままにする。**
- 固定の間隔の線に対する上積みは、2 つの決まりとも「seen」で、大きさは T37r が +7.18 %、F が +4.90 %。`evidence/19` が p 0.4 の 3 つの負荷で「見分けられない」と読んだものが、p 0.2 のこのマスでは 40 seed で 0 より上に出た。
- なぞり直しは、このマスの 5 段でも実機の遅れを 2.5 % の中で言い当てた。チケット 09〜12 がなぞり直しの採点で候補を絞る段取りに、このマスでの裏付けが 1 つ増えた。

## 読むときの注意

- **sweep の間、同じ 6 コアの機械で別の仕事が動いていた。** 02:40 から 03:40 ごろにかけて、単体試験・lint・分析の下書きが `nice -n 19` で、1 つずつ動いていた。1 本あたりの時間に差は出ていない。`meta.json` の run ごとの長さは 200 本とも 157.6〜158.4 秒で、この窓に入った 23 本の平均が 158.15 秒、残りの 177 本が 158.10 秒。sweep 全体の 1 本 159.5 秒は、始まりから終わりまでの 8 時間 51 分 42 秒を 200 で割った値で、run と run の間の後片付けを含む。200 本とも有効で印は 0 で、**この件について見ているのは有効性の印だけ**なので、別の仕事が測定の中身を動かしていないことまでは確かめていない。
- **確かめ役は 3 つ通した。** `spec.md` との突き合わせ、`perrun.py` と `ana.py` を 1 行も開かずに evalagg の csv から数を出し直すもの、入力を書き換えて穴を探すもの。出し直した数は、合否の線 2・3・4 の印字されている桁が全部一致した。書き換えて試した入力は、seed を 1 つ落とすと全部の読みが `incomplete` になり、F と T37r のラベルを入れ替えると得も入れ替わり、遅れを 1 つ・2 つ・3 つ 1.10 倍すると読みが predicted・mixed・missed と移り、腕の 3 点が単調に下がらない値を入れると `no line` になり、予測の定数の数字を 1 つ変えると script が止まる。指摘は 12 件で、**どれも数を 1 つも動かさなかった**。10 件は台本を硬くする直しにした（下の「作り直し方」の項）。残りは、この README と `RUN.txt` が無かったことと、帯の端の印字の丸め（`results.md` の最後の節に書いてある）。確かめ役の 1 つは「10.043 秒の腕の打ち切りが得を控えめにしている」と書いたが、数えると 10.043 秒の腕はどの得にも入っておらず（下の注意）、その読みは採っていない。出し直した 2 つとも evalagg の `discovery.csv` と `polls.csv` に乗っているので、**evalagg 自身の遅れと窓の定め方は、この 3 つのどれも見ていない**。
- **外のレビューを 1 回通した**（pi の glm-5.3-flash、読むだけ。`spec.md`、`predict.txt`、`results.md`、この README、`RUN.txt`、map の項、チケットの結果）。数字と読みの言葉の食い違いは 0 件。指摘は 1 件で、この README が得の大きさを「5〜7 % ほど」と丸めて、F の +4.90 % を高く見せていた。点の値に書き直した。レビューが確かめていないと言った所: 別の仕事が動いていた窓の本数と秒数、`RUN.txt` の git の行数と d009cfb の src での回し直し、確かめ役の件数。
- **打ち切りは `s10b10p043` の 2 本だけ。** seed 135 が 40 件、seed 149 が 4 件で、合わせて 44 件 / 9600 件。残り 4 段は 0 件。なぞり直しの予測はどの段も 0.000 だった。
- **得は、実のところ腕 2 つの間の線に対する得。** 2 つの決まりの状態確認の数は、全標本でも 2000 回の取り直しの 2000 回とも、6.0 秒の腕と 3.695 秒の腕を結ぶ区間の中に入った。**10.043 秒の腕は、どの得にも入っていない。** 打ち切りのある唯一の腕がその 10.043 秒の腕なので、上の打ち切りは得に届いていない。「腕 3 つの線に対する得」という呼び方は、このマスでは腕 2 つの間の線に対する得を指す。
- **`spec.md` の「レコードをまとめた平均と seed ごとの平均が一致する」は、`s10b10p043` では厳密には成り立たない。** 打ち切りの無い 4 ホップ先のレコードは、ほとんどの seed が 240 件なのに、seed 135 は 200 件、seed 149 は 236 件。この段のまとめた遅れは、seed を届いた件数で重みづけている。`spec.md` は凍らせてあるので、ここと `results.md` に書いて残す。
- **区間の幅は、なぞり直しの予測とほぼ同じだった。** 実測の半幅は T37r 5.37、F 4.33、差 3.80 ポイントで、予測の 5.01、3.92、4.52 の 0.84〜1.11 倍。`spec.md` は `evidence/19` の p 0.4 の経験から「実測のほうが 1.4 倍ほど広く、5〜7 ポイントになるかもしれない」と書いていたが、そこまで広がらなかった。理由は調べていない。
- **F を選んだのは seed 1〜20 で、読んでいるのは seed 121〜160。** 2 つは重ならないので、F にとってこの読みは標本の外。`fpin.txt` の標本の中の +11.1 のうち、どれだけが仲間の力でどれだけが 20 seed の偶然だったかは、この段だけでは分からない。
- **3 つの決め方の L と M については、この段は何も言っていない。** 決定器を 1 つも回していない。基準を置いて、物差しの seed の切断の時刻表を残すところまで。どれが良いかはチケット 12 が読む。
- **先を知っている V との距離が届くかどうかも、この段は何も言っていない。** `evidence/18` は `V_at_F − F` を +70.1 ポイント（+63.9〜+76.1）と出しているが、V はレコードが作られる時刻も線が落ちる時刻も知っている。ノードが判断の時点で自分で見られるものからその距離に届くかは、ここでは読んでいない。
- 1 つのマス（p 0.2、`w0`、`s6` の切断の形）だけ。ほかの p にも、ほかの負荷にも何も言えない。T37 と、3.695 秒より下の 4 つの腕も回していない。
- **なぞり直しの数は、全部なぞり直しの数。** 帯は「なぞり直しが実機をどう見込んだか」を言うもので、それ自体は実測ではない。±6 % は `evidence/13` が今の負荷で見せた最大のずれ 5.9 % から置いた幅で、段ごとの集計（Mode B）の幅であり、判断 1 回ごとの一致を言う幅ではない。
- **物差しの seed の切断の時刻表が、この run で見えるようになった。** `spec.md` が置いた約束は「この入力を、学習・ラベル作り・候補の選び・調整のどれにも使わない」で、コードでは縛られていない。
- `spec.md` に選びの余地があった所は 10 個。`results.md` の最後の節に並べてある。どれも、今回の数では読みを変えない。

## 作り直し方

`RUN.txt` の順。集計の中間の出力は置いていない（`evalagg` で作り直す）。2 回回すと、`perrun.csv`、`results.csv`、`results.md` は 1 バイトも違わない。

run の後に `perrun.py` と `ana.py` を 10 か所硬くした。やったことは、polls の行が欠けた run で止まる、判断の行が 1 行も読めなかった段を落とす、取り直しが 1 つも残らなかった枠を `no line` と読む、seed と負荷が決めたとおりかを見る、`meta.json` の commit を段ごとに出す、打ち切りと得が乗る区間を数えて出す、文言を `spec.md` の字面に合わせる、など。**実機の数では、どれも 1 つの数字も 1 つの読みの言葉も動かしていない。** 動いたのは、足した表と行と、書き直した文だけ。
