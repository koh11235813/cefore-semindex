# s5short / s5wait の状態確認の位相そろい（2026-11-05）

対象は s5short・s5wait・s5b10p043・s5b3p695・s5c の p = 0・0.2・0.4、seed 1〜20（300 run、evalagg の runs.csv で全部 valid）。窓は evalgen の [t0+10 s, t0+130 s]、t0 は h0 の agent_start。

## 結論
- 全ノードが同時に再試行して位相が揃う現象は、どの方針・p でも出ていない。8 本の向きのうち 3 本以上が ±50 ms 以内に再試行した塊は s5short・s5wait で 0（最大 2 本）、基線でも 3 本が数回あるだけ。他ノードの再試行との重なりは、近傍密度で見た偶然の、方針の段で 0.8〜1.3 倍（s5wait 0.78〜1.22、s5short 1.19〜1.28）、基線で 1.1〜1.9 倍（表 2 の「他ノード」の比。表 1 の excess は全部の poll で見た別の尺度）。
- 全 poll で見た map.md の尺度でも、excess は 0.9〜2.4、offset drift は 410〜4113 ms で、ゆらぎありの t2j*（0.65〜2.0 倍、41〜1406 ms）と同じ帯域。固定間隔 t2i*（2.8〜100 倍、1〜35 ms）のような位相固定は無い。基線の p = 0（b10p043 1.72/0.06、b3p695 1.53/0.14、s5c 0.98/0.11）は map.md の t2j10p043・t2j3p695・s1sub の範囲に収まるので、数字は比べられる。
- s5wait だけに出る性質: 同じ向きの続く再試行は slot 位相（5 s 格子）を保つ（±50 ms 以内が 86〜88 %、s5short は 0 %）。だから長い停止の間に両端の再試行が一度重なると、そのまま重なり続ける。s5wait p0.4 の link_reverse の persist 0.32 は map.md のゆらぎ帯（0〜0.27）を超える唯一の値だが、重なりは 2428 poll のうち 66 回、再試行どうしでは 14 回中 6 回で、そのうち 4 回は seed 14 の 1 run。薄い。
- 前半と後半: 10.043 s の 3 段の 18 か所のうち 13 か所で、重なりが後半に減る（開始時のそろいが崩れていく）。増えたのは s5short p0.4 の 2 つ（link_reverse 0.022→0.030、same_holder 0.027→0.029）、s5wait same_holder の 2 つ（0.012→0.023・0.013→0.026）、s5b10p043 p0.2 same_holder（0.022→0.023）。s5wait same_holder の重なりは、前半 802 回のうち 10 回から後半 794 回のうち 18 回（p0.2）、914 回のうち 12 回から 917 回のうち 24 回（p0.4）で、ノイズの範囲と見ている。

## 再試行の slot 位相のかたより（測った事実と推測）
- 測った: s5wait の再試行の slot 位相は 0〜1.5 s に寄る（<0.5 s が 0.14〜0.15、一様なら 0.10）。全 poll の位相も、10.043 s の 3 段（s5b10p043・s5short・s5wait）すべてで前半に 0〜1.5 s が 2.5〜4 s の約 3 倍、後半でならされる。方針によらない。最初の state_poll は全ノードで t0 + 515 ms 前後（450〜800 ms、外れ 1.1〜1.2 s が少し）。
- 推測: 全エージェントが t0 + 0.5 s ほどで一斉に最初の poll を出し、10.043 s ≈ 2 slot なので、開始の位相が slot 格子に対してしばらく残る。s5wait はちょうど 5 s で再試行するので、この位相を停止の間ずっと持ち越す。5 s の待ちが位相を格子に引き込んでいるとは見ていない。原因は実験の作り（同時起動と 10.043 ≈ 2×5）のほうと見ている。
- 影響: link_up 後 0.5 s 以内に送った再試行は s5wait 0.096・0.079、s5short 0.079・0.050。位相が一様なときの条件付きの偶然（(1 − down 中の割合) × 0.1）は s5wait 0.081・0.058 で、わずかに多いだけ。その 0.5 s 以内の再試行は、エミュレーションでは 1 回も失敗していない（s5wait 112 回、s5short 103 回とも 0）。2.7 % の残りの失敗はリプレイのモデルの仮定で、この計測からは出ない。
- リンクが落ちている間に送った再試行は s5wait 0.19・0.42（ほぼ p。次の slot に必ず移るので）、s5short 0.39・0.57（3.695 s では同じ down slot に落ちることがある）。再試行の失敗は s5wait 72/383・398/943、s5short 186/487・711/1254。
- link_up から次の poll までの中央値は s5wait 1.91・1.69 s、s5short 2.31・2.17 s、b10p043 4.7 s、b3p695 1.9 s、s5c 1.0 s。

- 他ノード = 送り手の違う 6 本の向きの再試行、同送り手 = 同じノードのもう一方の隣への再試行、逆向き = 同じリンクの反対の向き。括弧は近傍の偶然（±2.5 s 内の密度を ±50 ms に換算）に対する比。trial04 の巡回ずらしの偶然（0.005 前後）は、停止区間に閉じ込められた再試行には低すぎるので、比は local のほうを見る（巡回ずらしでは 4〜40 倍に見えるが、閉じ込めのせい）。
- head = link_up 後 0.5 s 以内でリンク up 中に送った割合。条件付き偶然は (1 − down 中) × 0.5/5。b10p043 の再試行は 10 s 後なので、この偶然は当てはまらない。
- dphase = 同じ向きで 12.5 s 未満で続く再試行どうしの slot 位相の差。
- 基線には reschedule の行が無いので、「再試行」は state.last_poll_status == timed_out の poll（失敗の直後に予定どおり出した poll）。方針段では reschedule から決めた件数と一致した。s5c の 1.6〜2.4 s の poll は前の poll の結果が出る前のことがあり（pending）、そのぶん少なく数える。

## 作り直し方

`phase.py` を README の「作り直し方」のとおりに回す（evalagg の `runs.csv` で valid な run を選び、`evidence/04/` の `trial04.py`・`breakdown2.py` を中身を変えずに import する）。300 run でおよそ 45 秒。再試行の、run と送り手ごとの行（`retry_pairs.csv`、330 KB）も書き、ここには gzip にして `retry_pairs.csv.gz` として置いた。

## 別の台本での数え直し

`retry_recount.py`（出力 `retry_recount.txt`）と `retry_offsets.py`（`retry_offsets.txt`）は、`phase.py` と別に書いた数え直し。

- 復帰直後の再試行は、どちらで数えても 215 本（s5short 40 + 64、s5wait 38 + 73）。
- 失敗は、`retry_recount.py` では 4 本、`phase.py` では 0 本。4 本はどれも名目の link_up（t0 + `at`）の 1〜10 ms 後に送っていて、リンクが実際に切り替わる（results.json の時刻、約 9.6 ms 後）より前だった（`retry_offsets.txt`）。`phase.py` は実際の切り替えから数えるので、食い違いではない。
- 再試行の塊は、`retry_recount.py` が「どこかの 100 ms の幅に入る再試行の数」の最大で、s5short p 0.4 の 1 か所だけ 3 本（ほかは 2 本以下）。上の「最大 2 本」は互いに ±50 ms 以内の組で数えた値で、数え方が違う。
- 最初の状態確認は、t0 から中央値 514〜516 ms（最小 457 ms、最大 1133 ms）。
