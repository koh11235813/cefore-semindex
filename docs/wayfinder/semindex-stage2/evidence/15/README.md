# evidence/15: 入ったり止まったりする負荷と、時間切れにも反応する決まり（2026-11-17）

evidence/14 に残った二つの推しを、同じなぞり直し（`../13/replay.py`、手を入れていない）で確かめた。切断の時刻表は今の run のまま、レコードを作る時刻だけを替えている。

**ここの数字は全部なぞり直しの値で、替えた負荷にも、足した時間切れの一歩にも、照らす実測が無い。** どの実機 run を回す価値があるかの見当として読む。

## 先に結論

- **推し 1（生成が入ったり止まったりする負荷なら、最短 3.695 秒の決まり T37 が固定の間隔に勝つ）は、先に決めた読みでは「合っていない」。** 切断の無いマスで得は +8.1 % と +6.7 % だが、区間が 0 をまたぐ。
- **推し 2（時間切れのときに間隔を動かせば、切断ありのマスで得が戻る）は、「最短に戻す」形（T37r）で、先に決めた読みでは「合っていた」。ただし紙一重で、この README では「切断の多いマスでは合っていた、少ないマスでは分からない」と読む。** 「上限に延ばす」形（T37b）は合っていない。
- T37r は、切断の多いマス（p 0.4）で T37 より 13.5〜17.4 ポイント良い。3 つの負荷のどれでも、区間はまるごと正。固定の間隔に対しては、今の負荷で +6.6 %、+8.4 %（区間はまるごと正）、入ったり止まったりする負荷では +0.7〜+4.9 %（区間は 0 をまたぐ）。

## 結果

表と全部の値は `onoff.md`、`onoff_cells.csv`、`onoff_gain.csv`。

### 推し 1: 切断の無いマスでの T37 の得

| 負荷 | 見出しの得（早いレコードだけ） | 全部のレコードでの得 |
|---|---|---|
| W0 | +18.0 %（+13.5 〜 +22.4） | 同じ |
| WO | +8.1 %（−0.2 〜 +15.7） | +14.9 %（+9.6 〜 +20.0） |
| WV | +6.7 %（−1.4 〜 +14.6） | +12.3 %（+5.9 〜 +18.6） |

- 先に決めた読み（見出しの区間が、WO と WV の両方でまるごと正なら「合っていた」）では、**合っていない**。両方とも 0 をまたぐ。
- 全部のレコードでの値なら両方まるごと正になるが、そちらは打ち切りの偏りを含む（このマスで、全部のレコードでの打ち切りは 10.043 秒の腕 3.3〜3.4 %、T37 0.1〜0.2 %。早いレコードだけなら全部 0 %）。信じるのは見出しのほう。
- 見出しと全部で値が違うのは、採点するレコードが違うため（早いレコードは全体の 6 割ほど）。
- 得の点は正で、W0 の半分ほど。生成が続く時間が 60 秒から 20 秒に短くなると得が小さくなる、という向きとは合うが、この seed の数では 0 と区別できない。

### 推し 2: 切断ありのマスでの、T37 との差（見出しの得の差）

| 負荷 | マス | T37 の得 | T37r の得 | T37r − T37 | T37b − T37 |
|---|---|---|---|---|---|
| W0 | p 0.2 | +5.1 % | +6.6 %（+2.2 〜 +11.0） | +1.5（−6.1 〜 +9.3） | +1.2（−6.1 〜 +8.1） |
| W0 | p 0.4 | −8.9 % | +8.4 %（+1.6 〜 +14.8） | **+17.4（+7.3 〜 +26.5）** | +4.0（−2.7 〜 +9.4） |
| WO | p 0.2 | −5.2 % | +2.0 %（−6.1 〜 +10.4） | +7.1（+0.0003 〜 +14.2） | +1.0（−3.2 〜 +5.0） |
| WO | p 0.4 | −13.8 % | +1.7 %（−5.5 〜 +8.3） | **+15.5（+6.8 〜 +24.0）** | +4.7（−3.5 〜 +13.0） |
| WV | p 0.2 | −4.9 % | +0.7 %（−7.6 〜 +8.5） | +5.5（−3.6 〜 +14.5） | −1.1（−8.9 〜 +6.4） |

- 先に決めた読み（差の区間がまるごと正の場合が 6 つ中 4 つ以上で「合っていた」）では、T37r は 4/6 で**合っていた**、T37b は 0/6 で**合っていない**。
- 切断の無いマスでは、3 つの決まりは同じ数字になる（時間切れが起きない。確かめた）。
- T37r は状態確認を多く使う（p 0.4 で 180 回前後、T37 は 140 回前後）。得は「同じ数の固定の間隔」との比べなので、数が増えたぶんは差し引かれている。
- 新しいものが来た答えのときの間隔は、p 0.4 で T37 6.0〜7.0 秒、T37r 4.7〜5.0 秒、T37b 7.4〜8.1 秒。T37r は切断明けに短い間隔で聞いている。

### 結果を見た後に足した測り（`after.py`、`after.md`。`spec.md` には無い）

T37r の「4/6」の 4 つ目（WO の p 0.2）は、区間の下の端が +0.0003 %。この薄さだと、`spec.md` が決めていなかったことで読みが変わる。採点・線・取り直しを別に書いて、どれだけ揺れるかを測った。

| 測ったこと | 結果 |
|---|---|
| WO の p 0.2 で、差が 0 以下になった取り直し | 2000 回中ちょうど 50 回。下の端（2.5 % 点）は 50 番目と 51 番目のあいだなので、分位点の取り方しだいで負になる |
| 取り直しの乱数を替えた 25 通りで、区間がまるごと正の場合の数 | 3 つが 15 通り、4 つが 10 通り |
| 早いレコードの区切りを t0+60 秒にしたとき | 3 つ（25 通りとも） |
| p 0.4 の 3 つ | どの測り方でも、まるごと正（差が 0 以下の取り直しは 2000 回中 1、1、24 回。区切り 60 秒で 1、1、11 回） |
| p 0.2 の 3 つ | 0 以下の取り直しが 702、50、243 回（区切り 60 秒で 871、332、586 回） |

- だから「合っていた」は、先に決めた線の上では成り立つが、線を引き直さなくても、乱数しだいで「まちまち」になる。**確かなのは p 0.4 の 3 つまで。**
- この別の台本の差は、6 つとも `onoff_gain.csv` の値と一致した（数え直しを兼ねている）。
- 見出しの区切り（72 秒）でも、p 0.4 のマスには打ち切りが残る（10.043 秒の腕 3.3〜5.0 %、T37 0.2〜3.3 %、T37r 0 %）。T37 は 10.043 秒の腕と 6.0 秒の腕のあいだ、T37r は 6.0 秒と 3.695 秒のあいだに落ちるので、偏りは T37 の得を下げ、差を大きく見せる側に働く。区切りを 60 秒にして打ち切りを 0〜2.7 % に下げても、p 0.4 の差は +17.0〜+19.7 ポイントで、小さくならなかった。

## 測ったもの、推したもの

測った（なぞり直しの上で）: 上の表。

推した（測っていない）:

- 切断があると T37 の得が消えるのは、切断のあいだに空でも新しいものでもない「時間切れ」が続き、間隔が延びたまま切断明けを迎えるためだと見ていた。最短に戻す形で p 0.4 の得が戻ったので、この見方は p 0.4 については支えられた。p 0.2 では切断が少なく、差が小さくて見分けられない。
- 上限に延ばす形が効かないのは、空の答え 2 回で間隔がもう上限に着いていて、時間切れのときに延ばす余地がほとんど無いためだと見ている（レビュー役の追跡では、時間切れのうち間隔が上限より短かったのは 1 本の run で 24 回）。「延ばすことを試して、効かなかった」とまでは言えない。
- T37r は、切断ありのマスで固定の間隔と並ぶか少し上、切断の無いマスで上、という形になった。今ある `short`（時間切れで 10.043 → 3.695 秒）と同じ向きの工夫で、`short` は切断ありのマスで −8.4 〜 +6.6 %。二つを直接比べる読み方は先に決めていないので、ここでは並べるだけにする。
- 学習の方針について: 式で書いた決まりでも、時間切れの扱いを一つ足すだけで、切断の多いマスの得が 13〜17 ポイント動いた。方針が見るべき入力に「直前が時間切れだったか」が入っていることは大事だと見ている（今の判断の状態には `consecutive_poll_timeouts` がある）。固定の間隔に対する上積みは、この負荷の形では数 % で、0 と見分けられないマスが多い。

## 確かめたこと

- W0 は evidence/14 の `workload_cells.csv` を、共通の 30（マス × 決まり）全部で、17 列とも印字した桁まで再現する。全部の決まりを派生クラスで回しているので、派生クラスが今ある決まりを変えないことの確かめになっている（`onoff.py` が最初に確かめ、合わなければ何も書かずに止まる）。
- 切断の無いマスで T37、T37r、T37b は同じ値（集計の列と、100 本ぶんの元の数の両方で。`onoff.py` が確かめる）。
- レビュー 2 人: 派生クラスが、いちばん新しい状態確認の時間切れにだけ効き、次の時刻を答えのときと同じ式で出していることを、ソースと 108 本の出来事の突き合わせで確かめた。負荷の生成は、`spec.md` の文から別に書いたものと 96 通りで一致。`onoff_gain.csv` の得と差は別の台本で数え直して一致。指摘のうち、`onoff.md` が古い台本の出力だった点は作り直した。読みが紙一重である点と、72 秒の区切りでも p 0.4 に打ち切りが残る点は、上の「足した測り」に入れた。
- 作り直すと csv はバイト単位で同じ（`RUN.txt`）。ruff は clean。

## 読むときの注意

- 替えた負荷も、時間切れの一歩も、実測と照らしていない。
- 作る時間と切断の時刻の重なり方は seed 任せで、そろえていない。T37r が得をするのは、切断明けにレコードが流れているときなので、重なり方で値が動く。
- マスどうしで負荷は同じではない（負荷の乱数の種に p が入っている）。切断の無いマスは `s5` の run で、`s6` には p 0 の run が無い。マスをまたいで読むと、切断の有無のほかに二つの違いが混ざる。推し 1 と 2 の読みは、どちらもマスの中の比べ。
- WV はレコード数が seed で 52〜312 と大きく違う。
- `onoff_gain.csv` の `save` の列の区間は、2000 回より少ない取り直しに乗っているものがある（少ないもので 1642 回。`boot_n_save` の列）。この README は `save` を読んでいない。
- 取り直しの単位は seed で、5 回の平均を seed の値にしている。
