# 空の答えが続いた後、次の答えはどれだけ空か（`s5*`・`s6*`）

`evidence/11/` が測らずに残した問い「直前までの答えが空だったことから、次の答えが空かどうかをどれだけ当てられるか」に答えるための数え直し。当たるなら、空が続いたら状態確認を間引く形の決まりが作れる。当たり方に癖があるなら、その癖を式で書けるのか、学習に任せる余地があるのかの材料になる。

run は新しく回していない。`evidence/11/` と同じ `s5*`・`s6*` の 840 本（42 マス、向きつきの組 6720 個）を読み直しただけ。

## 数えたもの

単位は run ごとの向きつきの組（ノード、隣）で、窓は `[t0+10 秒, t0+130 秒]`。定義は数える前に決めて、`streak.py` の docstring と `tables.md` の Legend にそのまま置いた。

| 数 | 中身 |
|---|---|
| 空の答え | `evidence/11/` の `rx_no_new` と同じ。答えの `hi` に載っている origin のすべてで、seq 1..hi をノードがすでに持っていた答え |
| `k` | その答えの直前に、同じ隣からの空の答えが何回続いていたか。前の答えが空でなかったとき、前の答えが無いときは 0 |
| `seen_new` | それより前に、同じ隣から空でない答えが一度でも来ていたら 1、まだなら 0 |

- `k` と `seen_new` は、ファイルの先頭からの答え全部でたどる。窓より前の答えは数えないが、履歴には入る。
- 数えるのは窓の中の答えだけ。だから組ごとの和は `evidence/11/perpair.csv` の `state_rx`・`rx_no_new` に一致する（確かめた）。
- `k` の区切りは 0、1、2、3、4、5〜9、10〜19、20 以上。
- 決まりの読み: 「`k` が K 以上なら次は空と言う」という旗を K = 1、2、3、5 で立てて、当たった数（`hit`）、外した数（`miss`、旗が立っていたのに空でなかった答え）、旗の中で当たった割合（`precision`）、空の答えのうち旗が立っていた割合（`recall`）を出した。

`k` も `seen_new` も、ノードが自分で数えられる。答えが届いた時点で空かどうかを計算できること（`evidence/11/` の結果の 4.）だけに頼っている。

## 測ったもの、推したもの

- 測った: `k` と `seen_new` ごとの答えの数と空の数、K ごとの旗の当たりと外れ、外れた答えが初めて見せたレコードの数、最初のデータが届くときの `k` の向きごとの散らばり。
- 推した（測っていない）:
  - 来る前の側で空が続くほどデータに近づくのは、生成が始まる時刻がどの run でも t0+13 秒で、最初のレコードが届くまでの状態確認の回数が origin からの遠さでほぼ決まるからだと見ている。2. の向きごとの散らばりはこの見方と合う。そうだとすると、この傾きは「生成がいつ始まるかが決まっている」この負荷の性質で、空が続いたこと自体が何かを知らせているわけではない。生成の始まりが不規則な負荷で同じ傾きが出るかは分からない。
  - 間隔の短い腕の谷は、生成の周期を `k` が刻んでいるためだと見ている。生成は 2 秒ごとで、0.5 秒の腕は 1 周期に 4 回ほど、1.359 秒の腕は 1〜2 回の状態確認を送るので、谷の位置（k = 3、k = 1）はこの見方と合う。台本は生成の時刻も状態確認の間隔も読んでいないので、確かめてはいない。
  - 来た後の側の当たり方（空が 2 回続いたら次も空）は、`evidence/11/` で推した「空が続くあいだ間隔を延ばし、新しいものが来たら戻す」形の決まり（Trickle、RFC 6206）がねらう場面にあたる。ただし 3. のとおり、この負荷といまの間隔では、そこに入る空は空の答えの 8〜22 % に留まる。窓が生成の終わりから 59 秒で閉じ、10 秒ほどの間隔ではそろった後の答えが 1 組に数個しか無いためだと見ている。生成が止まった後が長く続く負荷なら、この場面の取り分は大きくなるはず。
  - 式で決まる方針と学習された方針の比べについて。この負荷で `k` と `seen_new` から読めるのは、(a) 来た後に空が続いたら空、(b) 来る前は続くほどデータに近い、(c) 間隔が生成の周期より短いと `k` の小さいところに谷が出る、の三つで、どれも式で書ける。(a) は Trickle の形、(b) と (c) は生成の時刻や周期を知っていれば書ける形。学習に任せる余地が出るのは、(b) や (c) にあたる癖が前もって分からない負荷だと見ている。いまの負荷は、始まる時刻も周期も決まっている生成の山が 1 つあるだけなので、この比べには向かない。
  - 空でない答えのすぐ後の空（空の答えの 30〜35 %）は、空の続きからは読めない。隣の `hi` の進み方や時刻など、ほかの入力から読めるかは測っていない。

## 読むときの注意

- **旗の当たりは、省けたバイトではない。** ここの数は、いまの決まりで実際に届いた答えを後から分けたもの。状態確認を省いたり遅らせたりする決まりに替えると、その後に届く答えそのものが変わる（省けば答えが無いので `k` は進まない。外れた旗のぶんのレコードは、後で見つかる）。`recall` と当たりのバイトは「空の続きを数える旗が、空のどれだけに立つか」、外れは「その旗がどれだけ間違うか」で、省いたときのバイトの減りでも、遅れの増えでもない。遅れがどれだけ増えるかは、替えた決まりで回すか、なぞり直すかしないと分からない。
- `k` は答えの回数で、時間ではない。方針は失敗の後に間隔を変えるので、同じ `k` でも経った時間は run の中で違う。答えの無かった状態確認は `k` に入れていない。
- `seen_new` = 0 で k = 0（前の答えが一つも無い）の答えは、窓の中には無い。どの組でも最初の答えは窓より前（t0+0.55 秒あたり）に届いている。
- k = 3 から上の区切りは、6 マスでは答えが少ない（来た後の側の k = 3 と 4 で 1〜69 個）。区切りごとの割合は目安。K = 5 の旗の `precision` の seed の平均は、旗が 1 つでも立った seed だけの平均で、6 マスでは 4〜10 本（`cells.csv` の `precision_K*_nseeds`、`tables.md` の Table B の seeds の列）。
- 側の origin の決め方には頼っていない（空かどうかは `hi` に載った origin の全部で判定している）。ただし、最初のデータが届くときの `k` が origin からの遠さで決まるという読みは、直線のトポロジーと、両端の origin という置き方の上での話。
- p 0.5・0.6 には `REP_B` の値が無いので、バイトの列は p 0・0.2・0.4 のマスだけ。
