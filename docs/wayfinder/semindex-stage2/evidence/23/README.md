## 候補 a と b のどちらを採ったか

**採ったのは候補 b で、段取り自身の言葉での読みは「分かれたが、決め切れていない」である**（`ana.txt` part 4、"SEPARATED, NOT RESOLVED"）。

| 何 | 値 |
|---|---|
| 点の差（a − b） | 617.840 ms、低いのは b |
| 「小さい」の線 | 1.685586 ms/回 × 176.220 回 = 297.0340 ms、決まりとしての線は 297.0 ms |
| 対の bootstrap の 95 % 区間 | -58.424〜1357.299 ms、0 を挟む |
| 線のうち打ち消し合わない分 | 1.685586 × \|103.825 − 142.959\| = 65.963 ms |

差 617.840 ms は線 297.0 ms を越えるので、ラベルを付け直す道（利用者の決めたこと 6）は開かず、点の低い b を次のチケットへ渡す。ただし差は対の bootstrap の 95 % 区間の中にあり、その区間は 0 を挟む。だから段取りは「分かれた」と「決め切れていない」を並べて書く形を、点を 1 つも見る前に決めてあった（`spec.md`「How the choice between a and b is made」）。

線 297.0 ms は、重みの jackknife の標準誤差 1.685586 ms に 176.220 回を掛けた値である。この 176.220 回は、`../22/weight.txt` の段 4 が seed 1〜100 で取った外側の 2 本の腕の確認回数の平均 95.985 と 256.455 の中ほどで、上の表に出るこの csv 自身の 96.029 と 256.491 とは別の数である（`ana.txt` の part 2 の末尾が、この 2 組を混ぜないよう断っている）。線は、**重みを別の seed の引きで解き直したときに 1 本の点が動く量**である。差の信頼区間ではない。`../22/weight.txt` のもう 1 つの読み（40 本の流れごとの重みの半幅 3.676 ms/回、176.220 回で 647.8 ms）より狭いほうを採っているので、**「分かれた」は 2 つの枝のうち証拠の弱いほうの枝である**。重みの誤りは 2 つの候補の点を同じ向きに動かし、確認回数が近いぶんだけ打ち消し合う。打ち消し合わずに残るのは 65.963 ms で、これは点が出た後にしか計算できないため、決まりには使わず報告だけする。

**得のほうは 2 つの候補を逆の順に並べる。** 候補 a の得は 0.0411 で区間が 0 を外し、候補 b の得は -0.0058 で区間が 0 を挟む（下の表）。点が選ぶのは b、得が 0 から離れているのは a で、**2 つは別の遅れを別の向きで見た量である**（点は打ち切りを下限で入れ、得は落とす）。選ぶのは点だけである。

## 調整（2 回回して、重みは同じにならなかった）

### 2 回のあいだで点がどれだけ動いたか（これが n = 2 のばらつき）

| 前 | 後 | 差（ms） | 95 % 区間（ms） | 0 を挟むか | 前が低い seed |

### この測りが変える事と変えない事

**変えない事。** チケット 12 へ渡す候補は 2 回目の b のままである（A3）。`ana.txt` の読み「分かれたが、決め切れていない」も、5 つの予想の当否も、ラベルへの当たりも、1 回の判断の時間も動かない。1 回目のアダプタには `agree.py` も `latency.py` も回していないので、その 2 つについては 1 回目の数が無い。

**そのまま立つ文。** 「L は式の決まり F に勝たなかった」は立つ。2 回目の 2 つで言っていた事が、4 つのアダプタで言えるようになった。「固定 6.0 秒の腕とも見分けられていない」も立つ（4 つとも区間が 0 を挟む）。

**はっきりした文。** 「a と b の点の差が、2 つの絞り方の差である事は言えない」には数が付いた。b の 2 回のあいだの動き 634.457 ms は、a と b の差 617.840 ms より大きい。「この段を回し直して同じ数が出る事は言えない」も、点の単位で 448.515 ms と 634.457 ms という数になった。

**予想の読み替え。** 予想の当否は候補（2 回目）の数で読む。1 回目の数で読み替えても予想 1・2・4 の結果は変わらない（差 803.781 ms は線 297.0 ms を越え、F の 36150.829 は 1 回目の b の 36576.093 より低く、1 回目の a の得の区間 1.027 %〜5.548 % は 0 を外す）。予想 3 と 5 はラベルへの当たりを使うので、1 回目のアダプタでは読み替えられない。

**この測りが言わない事。** 2 回のあいだのどこで分かれたかは、この測りでも切り分けていない。4 つのアダプタを同じ 20 個の seed の上で見たので、2 回の引きの小さいほうを採った偏りは直らず、同じ seed を読む回数が増えただけである。3 回目の調整については何も言わない（`spread.txt` part 6）。

## 言えないこと

- **候補 b の 4586 行は、データだけから決まる数ではない**（Threats 15）。`../22/specnums.txt` が seed 1〜100 で数えた 1246 件は、2 位の腕が 3 位の腕と平均で並ぶ行で、t をどちらの腕に対して取るかは `ARMS` の並びが決めている。並びを替えると 2 件が選びの線を越える。平均を numpy で取り直した数え直しでは 4586 行より 1 行少なく出た（seed 12 の k 70、`RUN.txt` の 16）。
- **採点されたモデルは、最適化されたモデルと同じではない**（Threats 7）。学習の前向きは batch 16 の bf16 autocast、読み出しは batch 1 で autocast 無し（LoRA の枝は入力を float32 に寄せる）。**残した周は、最適化したのと別の計算の上の交差エントロピーを最小にした周である。** その差がどれだけかは、どこにも測っていない。
- **1 回の判断が 100 ms の周回に収まるかは、この段では決まらない。** `latency.txt` は GPU 1 枚の上の前向き計算 1 回を測った数で、ノードの機械でもノードの周回でもない。周回の問いはチケット 12 が持っている。

## seed 121〜160 を 1 度も使っていないこと（Acceptance 6）

**使っていない。どの台本も seed の一覧を門に通し、門が断る所を自分の出力で見せている。**

- **門は 2 つある。** `../22/port.py` の `check_seeds` が 100 を超える seed を断り（121〜160 はここで落ちる）、各台本の `check_seeds_tuning` が 80 を超える seed を断る（調整に使う一覧だけに当てる。`check_seeds` は 81〜100 を通すので、調整の門の代わりにはならない）。`decider.check_roles` は、役ごとの範囲と、役の合併が 121〜160 と交わらない事を確かめる。
- **役は出力に印字される。** 調整 seed 1〜70、残す周を決める seed 71〜80、候補を選ぶ seed 81〜100、合併と 121〜160 の交わりは 0 個。`tune.txt`・`eval.txt`・`ana.txt`・`agree.txt`・`latency.txt` の 5 つが part 1 でこれを印字する。`versus.txt` と `spread.txt` は役を 1 つも印字しない。どちらも csv の seed の列（最小 81、最大 100、20 個）と、その集まりが 121〜160 と 0 個で交わる事だけを part 1 に出し、シミュレーションもラベルの行も無いので csv の seed の列が持つ分より先の証拠にはならないと、自分で断っている。
- **シミュレーションは全部 `port.sim` を通る。** run の辞書が自分の `"seed"` を持つので、`port.Engine` の門が 1 本の道の上にある（`eval.txt` part 1）。
- **読んだラベルの行の seed も数えている。** `rows.txt` part 0、`agree.txt` part 1、`latency.txt` part 1 が、file の seed の最小・最大・個数（1、100、100）を印字する。
- **断る所を見せている。** `rows.txt` part 5（2 つの門）、`eval.txt` part 7（23 個）、`ana.txt` part 5（22 個）、`agree.txt` part 4（17 個）、`latency.txt` part 5（15 個）、`tune.txt` part 5（`decider.py` の 24 個と `tune.py` の 16 個）、`versus.txt` part 5（12 個）、`spread.txt` part 5（18 個）。`versus.py` と `spread.py`（`check_seed_roles`、`spread.py:138-152`）では、121〜160 の確かめを `check_seeds` より先に置いてある。逆の順では、121 はまず 100 の門に断られ、121〜160 の枝がどの入力でも動かなくなる。動けない枝は証拠にならない。
- **選びの側の seed 81〜100 を、点が出る前に読んだ所は 3 つある。追補 A2 が「2 つ」と数えたのは数え落としである。** 落ちていたのは用意の段の `parity.py` で、2 つの機械でなぞり直しが同じ byte になる事を確かめるために、seed 81 と seed 100 の流れ 0 を、モデルを呼ばない 4 つの決め方（固定の腕 3 本と F）で 1 本ずつ回し、その 8 本の点を `parity.txt` に印字している。段取りを固める前の事で、`spec.md` 自身がその中の数を 2 か所で引いている（seed ごとの点のばらつきの見当と、予想 3 の説明）。**L の設定、文、読み出し、候補の選びのどれも、この 8 本を使っていない。** ただ、本番の 4000 本のうちの 8 本の点は、段取りを書いた時点で作業者が知っていた（外のレビューが見つけた。`RUN.txt` の 27）。残る 2 つは追補 A1・A2 が書いた物である。1 つはラベルの腕ごとの割合の線 0.5273 で、これは生成済みの 2 つの file の引き算であり、モデルもシミュレーションも通っていない。もう 1 つは、リポジトリに無い手元の probe が `label.run_dict(0.2, 81)` を 1 回呼んで時間を測った事（切断の時刻表と記録の予定を組むだけで、シミュレーションもモデルの読み出しもラベルの行も無し）。`eval.py` の最初の確かめは、本番でも seed 1 を読む形に直してある（A1）。**点が出た後に seed 81 を触る所も 1 つある**（追補 A8）: `eval.py` の part 7 が、断られる事を見せるためにその seed の run の辞書を組み、port が最初の判断で断るシミュレーションを 1 本始める。csv が書かれた後なので、どの点にも届かない。

## 次のチケットへ開いたまま渡るもの

- チケット 12 へ渡る候補は b（`ana.txt` の "THE CANDIDATE THIS ANALYSIS CARRIES FORWARD: b"）。読みは「分かれたが、決め切れていない」で、点の差は対の bootstrap の区間の中にあり、得は 2 つの候補を逆の順に並べる。
