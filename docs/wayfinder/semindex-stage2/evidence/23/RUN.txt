2026-11-24.  No training in this step.  Two parts: the host, the inputs and the replay
(sections 1-5), then the first forward passes of the base model on that host (6-7).

WHAT THIS STEP ESTABLISHES
  1. A venv on the tuning host that sees the RTX PRO 5000 Blackwell as sm_120 and carries
     the gemma4 architecture.
  2. The base weights of google/gemma-4-E2B-it on that host, as plain files, pinned to one
     commit, with the content digest matching the hub's own LFS object id.
  3. The replay's inputs there: the hindsight labels, the 160 run files of the main cell,
     and the code at the relative paths two scripts on the replay path assert.
  4. That one port simulation produces the SAME BYTES on both machines, for six seeds and
     four deciders, although the two interpreters are python 3.12.13 and 3.13.5.
  5. That the checkpoint loads in bf16 on that card as Gemma4ForConditionalGeneration,
     that the chat template leaves the prefilled answer prefix as the last thing in the
     prompt, that " short" / " mid" / " long" each add exactly one token THERE, and that
     the three logits read out of one forward pass repeat bit for bit.
  6. What one pass costs on this card: 43.4 ms at batch 1, and 153.7 passes a second at
     batch 8, so 128 000 passes take about 14 minutes.

WHAT IT DOES NOT ESTABLISH
  Nothing about L as a decider.  No LoRA, no adapter, no training, no label-agreement
  number, and no decider in this step asks a model anything.  The model read out in
  section 6 is UNTUNED, so which of the three words wins a given prompt is not evidence
  of anything; only the mechanics are.  The four deciders of the parity check are the
  three constant arms and the formula rule F, i.e. the whole comparison except the
  candidate.  A forward pass on a GPU is not bit-reproducible across machines in general
  and nothing here claims it is: section 6 shows repeatability on ONE machine only.

  already proven on this card.  cu134 would rest on CUDA minor version compatibility
  against an older driver, which nothing here has tested.  So: cu132, pinned as

  merge them, because an extra index outranks the default in uv and numpy would then come
