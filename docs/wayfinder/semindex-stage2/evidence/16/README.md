# evidence/16: 時間切れで間隔を最短へ戻す決まりを、実機で測った（2026-11-18）

なぞり直し（evidence/13〜15）に残った差を、実機で確かめた。隣ごとに状態確認の間隔を 1 つ持つ決まりを 2 つ、切断の多いマス（`s6` の形、p 0.4）で 20 seed ずつ回した。合否の線と予測は、run の前に `spec.md` と `predict.txt` に置いた。

## 先に結論

- **なぞり直しの予測は当たった。** 2 つの決まりの遅れと状態確認の数は、4 つとも予測の ±6 % に入った（ずれは -0.4 %、-0.7 %、+5.6 %、-0.4 %）。時間切れに反応する決まりを実測と照らしたのは、これが初めて。
- **「戻す決まり（T37r）は、戻さない決まり（T37）より、固定の間隔の線に対して得が大きい」という差は、先に決めた読みでは「見えなかった」。** 差は +9.8 ポイントで、予測（平均 +15.9、範囲 +9.3〜+22.0）と同じ向きだが、区間は -2.2〜+19.7 で 0 をまたぐ。
- 40 本は全部有効。今ある 3 つの設定を新しいコードで回し直した 3 本は、判断の間隔が 1 行残らず設定どおりで、状態確認の数と遅れも元の run の幅に入った。

## 読むときの注意

- 「見えなかった」は、差が無いことを示していない。点の値は予測の範囲の下の端（+9.3）に近く、20 seed では区間の幅が ±11 ポイントある。予測では、40 通りのうち 38 通りで区間がまるごと正になるはずだった。実測がそうならなかった理由（点の値が小さめに出たためか、実機の seed ごとのばらつきがなぞり直しより大きいためか）は調べていない。
- 線は evidence/10 の 2 つの腕（2026-11-12 の run、別の版のコード）で引いている。今回の版で回した腕は seed 1 の 1 本ずつだけで、その 1 本どうしは元の run と数 % の中で合っていた。
- 固定の腕は 2 つで、そのあいだは両対数の直線と仮定している。なぞり直しでは、6.0 秒の腕（遅れ 29.744 秒、状態確認 159.4 回）は、3.695 秒と 10.043 秒の腕を結んだ直線より 0.9 % 上にあった（`predict.txt`）。実機でも同じなら、直線に対する得は、どちらの決まりも少し小さく出ている。実機の 6.0 秒の腕は測っていない。
- 1 つのマス（p 0.4）、1 つの負荷、1 つの切断の形だけ。ほかの p、ほかの負荷には何も言えない。
- 集計の点検の数 `hop_gap_outside_window` は、決まりの 2 段で 640 と 652（evidence/10 の同じマスの腕では 0 と 64）。ホップごとの内訳を作るときに窓の外の判断に当たった回数で、4 ホップ先までの遅れと状態確認の数には入らない。この段ではホップごとの内訳を読んでいない。
