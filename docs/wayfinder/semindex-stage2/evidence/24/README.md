## 候補 a と b のどちらを採ったか

**採ったのは候補 a で、段取り自身の言葉での判定は `CLOSE`（「近い」）である（`ana24.txt` 4 節）。**

| 何 | 値 |
|---|---|
| 点の差（a − b） | -102.566 ms（差の大きさ 102.566 ms、低いのは a） |
| 「小さい」の線（band） | 1.685586 ms/回 × 176.220 回 = 297.0340 ms、決まりとしての線は 297.0 ms（`ana24.txt` は 297.000 ms と印字） |
| 対の bootstrap の 95 % 区間 | -407.071〜222.470 ms、0 を挟む（a が低いのは 11 / 20 seed） |
| 線のうち打ち消し合わない分 | 1.685586 × \|140.670 − 148.390\| = 13.013 ms |
| 判定語と選んだ候補 | `VERDICT: CLOSE` / `CHOSEN CANDIDATE: a` |

段取り（`spec.md` 10 節）が点を 1 つも見る前に定めた規則の原文をそのまま引く。

> - `|gap| < 297.0 ms` -> **CLOSE**, and the user's relabelling clause of ticket 10 is not reached by this step;
> - `|gap| >= 297.0 ms` and the gap lies inside the paired bootstrap's 95 % interval -> **SEPARATED, NOT RESOLVED**;
> - `|gap| >= 297.0 ms` and the gap lies outside it -> **SEPARATED**.
>
> The chosen candidate is the lower one in every branch, because the user asked for a decision.

差 102.566 ms は線 297.0 ms より小さいので `CLOSE` に当たり、どの枝でも点の低いほうを採るという凍結した決まりに従って候補 a がチケット 12 へ渡る。`CLOSE` は 2 つの候補の差が小さい事を示す語であり、a を b より良いと判定する語ではない。チケット 10 の「分かれたが、決め切れていない」（`SEPARATED, NOT RESOLVED`）は差が 297.0 ms を越えた場合の語であり、今回はその手前である。297.0 ms の線は、`../22/weight.txt` が重みに付けた jackknife 標準誤差 1.685586 ms/回と、段 4 の外側 2 本の腕の確認回数 95.985 と 256.455 の中ほど 176.220 回の積であり、重みを別の seed の引きで解き直したときに 1 本の点が動く量である。差の信頼区間とは別の量であり、重みの誤りのうち 2 候補の確認回数の差から打ち消し合わずに残るのは 13.013 ms である（`ana24.txt` 4 節）。

## 固定の腕の折れ線に対する得

**F、候補 a、候補 b の 3 つとも得の 95 % 区間は 0 より上にあり、読みはすべて `seen` である（`ana24.txt` 3 節）。** 得は `1 - 遅れ(決め方) / 折れ線(その決め方の確認回数)` で、ここでの遅れは打ち切られたレコードを落として run ごとに足し上げた値、折れ線はこの段が回し直した固定の腕 3 本を log-log で結んだものである。点の遅れ（打ち切りを下限で入れる）とは別の量であり、固定 10.043 秒の腕では点の遅れ 29840.255 ms と得の遅れ 29813.457 ms に分かれる（`ana24.txt` 2・3 節）。

折れ線の 3 点（1 seed あたりの確認回数と、打ち切りを落とした遅れ、`ana24.txt` 3 節）は、固定 3.695 秒が 10259.650 回（256.491 回/run）・14060.180 ms（打ち切り 0.0000）、固定 6.0 秒が 6381.450 回（159.536 回/run）・20396.934 ms（0.0000）、固定 10.043 秒が 3841.150 回（96.029 回/run）・29813.457 ms（0.0008）である。`seen` と `not-seen` は区間が 0 のどちら側にあるかを書く語であり、合否の線ではない。候補 a の得 0.0546 にも、同じ 20 個の seed で 2 候補の低いほうを採った偏りが乗っている（`spec.md` Threats 5）。

## 学習の組み立て、最初の 1 歩での停止、run 内の傾きの後付け測り

**両候補ともペナルティ `lambda* = 0.0001` を選び、Check A と centring の門を通ったが、policy iteration は最初の 1 歩（k = 1）で rate の止めの基準を越えて止まり、記録方針の評価 `w_0` の greedy 方針をそのまま出した（`learn24.txt` 2 節）。また、当てはめた値は run の中の位置に沿って大きく傾いており、後付けの感度測りでも状態と時計の切り分けは付いていない（`drift24.txt` 1・3・6・7・9 節）。**

## ADR 0004 の警告に対して何をしたか（Acceptance 7）

**ADR 0004 が次の手として残した「模型を使わない順を追う学習」を、前提の模型を作らないまま採り（決まったこと 5）、組み立ての誤差が積もる所を「1 回の切断の連続手数（深さ）」から「直線の 8 組のつながり（幅）」へ読み直した。押さえたのは判断ごとの負担の和が run の点に一致する事だけで、残る 4 つは押さえていない**（`spec.md` 12 節、`outage.txt` 1 節、`charges.txt` part 1）。

ADR 0004 は、1 回の判断ごとの文脈つきバンディットと判断列全体の直接評価を退け、「先に作る模型の予測が検証で外れたら」の条件付きで bootstrapping による模型を使わない順を追う学習を次の手として残した。その際、0.5 秒の腕では 10 秒の切断が約 20 回の連続判断にまたがり、bootstrapping の誤差が積もると警告している（`spec.md` 12 節）。その先の模型は作られていないため（`../../map.md`「ADR 0004 のモデルは、まだ作っていない」）、この一手は前提を満たさないまま利用者の決まったこと 5 の下で進んでいる。

この腕の組（3.695・6.0・10.043 秒）で 1 回の切断に何回の判断が入るかは、この段で初めて `results.json` を開いた `outage.py`（seed 1〜20）が測った（`outage.txt` 0・1 節）。

| マス | 閉じた切断（未終了） | 向きつき組の区間数 | 切断の長さ（秒、最小 / 中央 / 平均 / 最大） | 1 切断・1 組の判断数（最小 / 中央 / 平均 / 最大） | 判断数の内訳（0 / 1 / 2 / 3 回） |
|---|---|---|---|---|---|
| p 0.2 | 202（22） | 404 | 0.575 / 9.626 / 9.467 / 12.000 | 0 / 1.0 / 1.168 / 3 | 54（0.134） / 233（0.577） / 112（0.277） / 5（0.012） |
| p 0.4 | 393（30） | 786 | 0.036 / 9.819 / 9.621 / 12.000 | 0 / 1.0 / 1.155 / 3 | 108（0.137） / 455（0.579） / 216（0.275） / 7（0.009） |

この腕の組では、1 回の切断に含まれる 1 組の判断数は中央 `1.0` 回・最大 `3` 回であり、ADR 0004 が 0.5 秒の腕で挙げた約 20 手とは形が異なる（なお `outage.txt` の算術は検証者の誰も再計算していない、`RUN.txt` 11.5 節）。

**誤差が積もる所の読み直し**: この段の 1 歩 bootstrap は向きつき 1 組の鎖の上で組んでいるが、レコードは 4 hop を渡り、ある組の期間内の待ちは下流の組の状態確認の位相に左右される（`charges.txt` part 9、`spec.md` 5・12 節）。したがってこの設計で誤差が積もる所は、時間方向の深さよりも、**直線の 8 本の向きつき組が互いに影響し合う幅**に移っている。

- **押さえたこと（1 つだけ）**: 判断ごとの負担の和が run 全体の点 `(lat + censored) + W × N × polls` に残りなく一致する事（`charges.txt` part 1、40 本すべて差 `0.0e+00`、p 0.4 の打ち切りレコード 120 件も越えられなかった hop に割り振って残差 `0.000000 ms`）。どの判断にも属さない先頭・末尾の負担は p 0.2 で `0.184 %`（最大 run は seed 19 の `0.809 %`）、p 0.4 で `0.228 %`（最大は seed 6 の `0.604 %`）にとどまる。
- **押さえていないこと（4 つ、`spec.md` 12 節）**: (1) 実機となぞり直しの判断 1 回ごとの一致（`../13/validate.md` の Mode A は不合格のままで、要る 42 マスに対して線に届いたのは 39・24・41 マスだった）、(2) 記録方針以外の方針の値に対する保証（実際に k = 1 で出した M の評価が止めの基準を越えた）、(3) 8 本の向きつき組のつながりの模型化、(4) 1 歩の bootstrap が誤差の積み上がりを免れている保証（記録方針の評価でも rate が -31.6327 ずれ、560 本の block 端点差がすべて正になった）。

## 言えないこと

`spec.md` 16 節の Threats 1〜19 と、`RUN.txt` 10〜12 節の検証で見つかった限りを、この結果を読むときに効くものとしてすべて並べる。

- **実機で学び、なぞり直しで点を付けている**（Threats 1）。`../13/validate.md` の Mode A（判断 1 回ごとの一致）は不合格のままで（要る 42 マスに対して線に届いたのは 39・24・41 マス）、M の係数は判断 1 回ごとの負担に当てはめている。**実機で当てはめた判断ごとの値が、なぞり直しが M に尋ねている判断を表しているとは言えず、実機での M の値についても何も言えない。**
- **記録方針以外の評価はすべて外挿であり、出した M 自身の評価は段取りの基準を越えて止まった**（Threats 2、`RUN.txt` 11.2 節）。ログは一様な記録方針の軌跡しか持たず、出した M（`pi_greedy(w_0)`）自身の評価である k = 1 の solve は a で `rho_1 = 8.8813`、b の p 0.2 で `12.4988` と、段取りの基準幅 `12.2238` を大きく越えて止まった（`learn24.txt` 2 節）。**M の当てはめ値や推定 rate が M 自身の時間あたり負担を表すとは言えず、段を重ねた改善が効いたとも言えない。**
- **当てはめた値が run の中の位置に沿って傾いており、状態と時計の切り分けが付いていない**（Threats 19、`learn24.txt` 2 節、`drift24.txt` 1・3・6・7・9 節、`RUN.txt` 10・11.2 節）。記録方針の評価の `rho_hat = 17.2626` は `R_fit = 48.8953` から `-31.6327` 離れ、560 本の block 端点差はすべて正（平均 `2917.0061`）である。決定時刻との run 内相関の絶対値が 0.5 を超える 40 個の欄を止めた `a_neutral` は学習 seed 1〜20 で +2806.790 ms 悪くなったが、その操作は状態の情報も消すうえ、選んだ間隔の決定時刻への傾きは `a_neutral` のほうが強い（`+0.036901 s/s` 対 `+0.012575 s/s`）。**M の腕の並べ替えが run の中の位置とは別の状態に反応した結果であるとは言えない。**
- **直線上の 8 本の向きつき組のつながりを模型に入れていない**（Threats 3、`charges.txt` part 9）。M の式は 1 組の鎖だけを扱い、他の 7 組を環境として値付けしているが、M を動かすと他の 7 組も M に変わる。**M の 1 歩 bootstrap が run の点を生む仕組みそのものを写しているとは言えない。**
- **F は 6 つの間隔から選べるのに対し、M は 3 つしか選べない**（Threats 4、`eval24.txt` 3・4 節）。差し込み口は `port.union_choices()` の 6 つの間隔を受け入れるが、ログが引いたのは 3.695・6.0・10.043 秒の 3 つだけである。**M の点が、より細かい間隔を学んだ方針の点を示すとは言えない。**
- **すでに 9 つの決め方が採点された 20 個の seed の上で 2 候補の低いほうを選んでいる**（Threats 5・6、`inventory_after.txt` 3 節、`ana24.txt` 2・3 節）。seed 81〜100 は `../23/eval.csv` の 7 つと `../23/spread.txt` の 1 回目アダプタ 2 つの計 9 つの決め方がすでに採点された組であり（ほかに `../23/parity.txt` の 8 本と `../23/spec.md` A2 の手元の試しがある）、段取りを書いた時点でそれらの平均点は既知だった。a の 35858.943 ms は 2 候補の最小値である。**35858.943 ms や得 0.0546 が候補 a の偏りの無い良さの見積もりであるとは言えず、予想や比べの相手が seed 81〜100 から独立であるとも言えない。** 偏りを直せるのは未読の seed 121〜160（チケット 12）だけである。
- **20 個の seed の区間は広い**（Threats 18）。40 個の seed を使った `../20` より半幅がおよそ sqrt(2) 倍広くなる見当である（推論であり計測ではない）。**a − F や a − b の区間が 0 を挟む事から、2 つの決め方が同じ性能であるとは言えない。**
- **M、F、固定の腕は同じ乱数を見ていない**（Threats 7、`eval24.txt` 2 節）。送信時と解決時で間隔を変える決め方は `../13/replay.py:1103-1109` の早い return を外れ、その組の乱数から `tick_lag` を 1 回多く引く。`eval24.txt` 2 節で気を変えた判断の割合は、固定の腕 3 本がすべて `0.0000` であるのに対し、F が `74681 / 156585`（`0.4769`、`lag_draws_total 266025`）、候補 a が `65424 / 125336`（`0.5220`、`210240`）、候補 b が `71082 / 131512`（`0.5405`、`224443`）である。最初の食い違い以降はその組の乱数の並び自体がずれる（`../22/README.md`）。**M と F や固定の腕との点の差が、決め方だけの差であるとは言えない。**
- **ペナルティ `lambda* = 0.0001` は記録方針の `Crit` で選んでおり、隣の格子点と区別も付いていない**（Threats 8・17、`learn24.txt` 2 節、`RUN.txt` 12.2 節 1）。`Crit` は記録方針の先 4 判断の当てはまりを `lambda_ref = 0.0001` の目標に対して測る量であり、greedy 方針の点を下げる量とは別である。また `1e-4` と隣の `0.001` の差（a `189789.341`、b `287789.168`）は各水準の `Crit_SE` と同程度にとどまり、対の差の標準誤差は出力に無い。**`lambda* = 0.0001` が M にとって最良のペナルティであるとも、隣の `0.001` と区別できているとも言えない。**
- **M が読めない欄と、数行しか動いていない欄がある**（Threats 9、`rows24.txt` 4 節）。候補 a の fit 行では 261 欄のうち `154` 欄（b は `151` 欄）が定数であり、標準化と正則化により重みは厳密に 0 に固定される（`pending` の状態確認、3 つめ以降の発信元 `o3_*`〜`o8_*`、省略フラグ、1 発信元あたり 3 つめ以降の広告主、丸められた間隔など）。また a で `o2_missing` は `7 / 7837` 行、b で `in_flight` は `2 / 15633`、`fetch_timeout_present`・`fetch_timeout_age_s` は各 `4 / 15633`、`o2_missing` は `12 / 15633` 行しか動いていない。**これらの欄が動く条件へ、この段の数がそのまま当てはまるとは言えない。**
- **数の列と文の一対一対応は、M と L の入力の道が入れ替え可能である事を意味しない**（Threats 10、`features.txt` part 3）。19291 件の記録で 18032 通りの文と 18032 通りの数の列が衝突 0 で対応するが、M は定数の欄を必ず無視し、fit 窓の `(mu, sigma)` で標準化し、送信時には模型を呼ばない。**M と L が同じ仕方で入力を使っているとは言えない。**
- **候補ごとに当てはめは 1 通りであり、L との比べは決定的な 1 解と引き直すたびに動く値を並べている**（Threats 11、`learn24.txt` 4 節、`../23/spread.txt` part 3）。M の当てはめは閉じた式で再現するが、行の集まり・窓・格子・特徴量の選び方は 1 通りだけである。一方、L は同じ手順を 2 回回すと候補 b が `634.457 ms` 動いた。**a と b の差が 2 つのマスのログだけの差であるとは言えず、L の 3 回目の調整との差がどこに来るかも言えない。**
- **M が見る入力は ADR 0004 が許した 2 つの欄（5 通り）より広い**（Threats 12、決まったこと 7）。**M の点から、ADR 0004 が許した情報だけの範囲で組んだ方針の点は言えない。**

## そのまま残している既知の欠陥と理由

**数値も出した M も動かさない欠陥と記録のずれは、digest がアーカイブと csv に刻まれているため単独では直さず、すべてここに記す（`RUN.txt` 11.3・12.2 節、`spec.md` 14 節）。** 出力がアーカイブ済みの台本や csv の `script_sha` が指す台本は、数字や決定を動かさない修正だけを単独で当てると digest が食い違うため、記録に残してそのまま置き、次に機能上の理由でその台本を直すときに合わせて直す決まりを `spec.md` 14 節が定めている。

- **`learn24.py` 326〜327 行の収束出口が到達不能である**: `k > 0` で配列と `bytes` を比べているため、`changed_k == 0` の収束出口を今のコードでは一度も通れない。出した M は `k = 1` の rate 基準で先に止まったため、係数も点も動いていない（`RUN.txt` 11.3 節）。
- **`learn24.txt` の `k = 1` 行で `changed` と腕の割合が `--` になっている**: `learn24.py` が rate 基準でループを抜ける前にそれらを計算していないためであり、`w_1` の greedy 方針が出した M とどれだけ違うかを出力から読めない（`RUN.txt` 12.2 節 5）。
- **`k > 0` の Check A が端点和の形式になっていない**: `m24.py` の greedy 枝は `chain[next_pos]` を行ごとに足す形であり、`spec.md` 4.7 節が挙げた端点和の形式と異なる（`RUN.txt` 11.3 節）。
- **`rows24.py` のほぼ定数の閾値 `non_mode <= 20` が `spec.md` に無い**: 印字だけの分類であり、当てはめ側で欄を落としてはいない（`RUN.txt` 11.3・12.2 節 3）。

- **`spec.md` 19 節 step 1 の記録が `RUN.txt` 8 節に無い**: `charges.py`・`precheck.py` 編集後の 4 台本の再実行と `cmp` は後から検証者と主の作業者が実行し、`charges.txt`・`features.txt`・`labelsig.txt` の byte 一致と `precheck.txt` の 400 行目までの一致を確かめた。なお `precheck.txt` part 7 の係数 digest は BLAS のスレッド数を 1 に固定すると変わる事が検証で見つかっている（`RUN.txt` 11.3 節）。
