1  THE THREE ROADS TO A RECORD, AND WHAT THEY CANNOT READ
==============================================================================
A logged row and a replay decision reach the vector through ONE function,
observe.observation, and the replay side goes through the port's own observation
dict -- the shape label.py's self-check and decider.py's L both build.  A send-
time decision, where there is no resolution, goes through the same road.

one logged row, rendered from its vector and back: 922 characters
the same row with every node name replaced by one of reversed alphabetical
order (h0->q9, h1->q8, h2->q7, h3->q6, h4->q5): the vector is unchanged
the same rename with the polled neighbour's OLD name put back on the action
alone, so the decision polls a peer the state no longer names -- a different
decision and not a leak: the vector is different, which is what says the equality above is not vacuous
one label row through the port shape, then with another node name and ordinal in
`where`: the vector is unchanged
the same label row with its own `node`, `k`, `rollin_arm` and `label` overwritten:
the vector is unchanged
the same row as a SEND decision (no resolution): it renders as 'state poll' and its
res_present cell is 0, against 1 at the resolution

What the vector cannot read, because `vector` takes the record and nothing else:
the node name, the decider ordinal, and the emulator's own action fields.  Of
those, `fetched` is worth naming: it is on no state_poll_reschedule row of these
runs at all (it is written on `fetch_plan` rows, which this road never reads),
and observe.from_logged_rows takes only the 3 resolution fields and the 6
exchange fields it names.

2  THE ROUND TRIP, OVER EVERY RECORD OF EVERY SOURCE
==============================================================================
For each record: render it, build its vector, invert the vector, render the
inverse, and compare the two texts character for character.  Every quantity the
text carries is therefore recoverable from the vector, at the rounding render
itself uses.  Also checked per record: the layout equals NAMES, every absent
slot is filled with 0.0, the record carries no node name, and the decoded record
passes observe.py's own schema.

  never polled, with no resolution, no origin and no exchange -- fails observe's

Two checks no input mutation can fail, named rather than left out:
- one text per vector (part 3's second direction).  `unvector` reconstructs every
  field `render` reads, so one vector determines one text by construction.  The
  way it COULD fail is a long input truncated into a short one's vector, which
  the three cap refusals above are what prevent, and a value hidden in the
  padding, which `fill/padding` is what prevents.
- that the vector reads no node name.  `vector`'s only argument is the record and
  the record has no name in it, so no input can make it read one.  What can be
  shown is part 1's equality under a full rename, part 1's difference when the
  polled name alone is left behind, and the `no name/in the record` refusal.

7  WHAT THIS MODULE DOES NOT SHOW

- Nothing about whether these features predict anything.  The round trip says
