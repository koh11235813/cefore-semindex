1. The order, and why it is this order
--------------------------------------
cd $W

$PY -B $E/weight.py       # writes weight.txt and weight.json
$PY -B $E/stability.py    # imports label.py, which reads weight.json at import; writes stability.txt
$PY -B $E/label.py        # reads weight.json; writes the two label files, labels.txt,
                          #   labels_summary.csv and labels.sha256
$PY -B $E/statecheck.py
$PY -B $E/lagcheck.py
$PY -B $E/valuecheck.py
$PY -B $E/labelcheck.py   # imports label.py
$PY -B $E/observe.py      # reads both label files; writes observe.txt
$PY -B $E/specnums.py     # reads weight.json and both label files, after checking their sha256 against
                          #   labels.sha256; writes specnums.txt
$PY -B $E/gate.py         # LAST, AND ALONE: see below

weight.py has to run first because stability.py and label.py read the number it writes. observe.py,
specnums.py and labelcheck.py read what label.py wrote.

stability.py is listed before label.py because it is what justifies the J the full labelling runs with,
and not because label.py reads anything it writes: stability.py's one output is stability.txt, label.py
never opens it, and the 8 passes are label.py's own `--passes` default. Running them the other way round
produces the same label files. A J other than 8 would have to be passed as `--passes` by hand.

gate.py runs last and alone. Its check 4 snapshots `git status --porcelain` and `git diff HEAD` at its
start and compares them at its end, so any other script writing a file while it runs makes it fail. It is
also the reason it is run after the prose of this directory is written and not before.
