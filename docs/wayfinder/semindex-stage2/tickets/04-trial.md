## Task

短い試走で、間隔の選択肢の値と k を決める材料を出す（map の Fog）。オーケストレータが root で回す。

- 間隔: k = 1 で、間隔を 1 つに固定した方針（チケット 01 の選択肢を 1 つだけ与える。たとえば 0.5・1・2・4・8 秒）を、p = 0 と 0.4 で seed 数個ずつ回す。間隔ごとに、遅れ（とくに状態確認の待ち）と通信量がどれだけ動くかを見る。選択肢は、遅れと通信量の両方が目に見えて動く範囲から選ぶ。
- k: 既定の方針で、k = 1・2・4・8 を p = 0.4 で seed 数個ずつ回す。1 度に取る件数の分布がどう広がるかと、run 1 回の保存量を見る。
- 間隔のゆらぎをやめた影響（map の Fog）: 選択肢を与えた方針で、ノードどうしの状態確認が同じ時刻にそろい続けていないかを見る。
- 選んだ値と根拠を、段 2 の map の決定に書く。本番の条件（切断率、seed の数、run の長さ）の案も出す（決定は利用者）。

## Acceptance

試走の run がすべて有効（印つき 0）。間隔ごとの遅れと通信量、k ごとの 1 度に取る件数の分布を表にして、この effort の `evidence/04/` に入れる。間隔の選択肢と k の値を map に決定として書く。
