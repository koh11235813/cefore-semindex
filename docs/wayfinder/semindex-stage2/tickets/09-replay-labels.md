## Task

なぞり直しに、**自分で見られる状態を読んで間隔を決める決め方**を差し込む口を作り、
そこに後から知った正解（hindsight のラベル）を作る道具を足す。
gemma も ML も、まずこの口の上で点を付けて候補を絞る。

中身は 4 つ。

1. **差し込む口。** `decide_interval`（`evidence/13/replay.py:653`）と `resolve`（`:727`）の両方に、
   `Node` から `tracker.decision_state` と同じ形を組み立てて渡す口を置く。
   `Node`（`replay.py:263-287`）には観測できるもの（`hi`、`extra`、`advertised`、`fetches`、`in_flight`、
   `consec`、`due`、`poll_ord`）がそろっているので、20 行ほどの組み立てで足りる（下請けの見積もり）。
   **`last_timeout_s` だけは今の `Node` に無い**ので足す。
   **隣の `_Origin.hist` は渡さない。** それはシミュレータだけが知るもので、実機のノードには見えない。
2. **候補のあいだで乱数をそろえる。** 今は Mode B の刻みのずれが 1 本の `sim_rng` から出来事の順に引かれるので、
   最初に変えた判断が、以後ぜんぶのノードのずれを動かす（`replay.py:627-636`）。
   直し方の先例が `evidence/18/bound.py:160-168` にある（隣の組ごとに `random.Random(f"...:{seed}:{node}:{nb}")` を 1 本持つ）。
   それを写す。**揺らぎの引きは何回目かで決まる位置の引きなので、判断の回数が変わる候補では、なおそろわない。**
   その残りのずれは、Mode B の通し数を増やして平均で押さえる。
3. **1 回の判断につく重み。** 点 = 遅れ + 重み × 状態確認の回数。重みは 1 つの数で、ラベルを作る前に固定する。
   決め方は「主のマスで、固定 3.695 秒の腕と固定 10.043 秒の腕が同じ点になる値」。
   `evidence/18/bound_cells.csv` の p 0.2・W0 の行から出すと
   `(30636.8 − 13934.6) / (256.09 − 95.78)` で状態確認 1 回あたり 104 ms になる。
   **この 104 ms は見当で、効く値はこのチケットで出し直す。**
4. **後から知った正解のラベル。** 1 回の判断について、3 つの腕を順に当て、run の終わりまで回し切って、
   点のいちばん良い腕をその判断の正解とする。

**作り方は、途中から枝分かれさせずに、run をまるごと回し直すやり方にする。** `copy.deepcopy` は動くが 2 つの意味で壊れる（どちらも測って確かめた）。heap に入っているのは `(t, prio, n, nb, counter, lambda)` の組で、deepcopy は関数を分けないので、写しの closure は元の engine を指したまま動く。`Node.jitter_rng` も束縛済みメソッドで分かれないので、写しと元が 1 本の揺らぎの流れを取り合う。しかも 1 回の回し切りと採点で 10.4 ms しかかからず、deepcopy の 21 ms より安い。

### この一手が示せること、示せないこと

**示せること**

1. **ラベルを作る値段。** 1 本を 6.4 秒の見当（判断 203 回 × 3 腕 = 609 回の回し切りで 6.34 秒。
   `s9wo_t37r` の p 0.4 seed 1 で測った）。**この数を測った台本はこのリポジトリに残っていない。**
   しかも同じ run の判断の回数が 203 回とも 204 回とも報告されているので、1 本あたりの回数は
   **測り直す見当**として扱う。この一手が同じ run を回すので、そこで数え直して書く。
   200 本・通し 1 回で 1 コアで 21〜29 分、96 コアで 13〜18 秒（1260 秒と 1740 秒を 96 で割った値。
   pool の上積みは入れていない）。**値段は詰まる所ではない。**
2. **gemma と ML が同じ入力を見ること。** 観測できる状態の文字にする道を 1 つにして、両方がそれを呼ぶ。
3. **重みの効く値。** 上の 3 の定め方で出した 1 つの数。

**示せないこと**

- **ラベルが実機の正解であること。** ラベルはなぞり直しの中の判断の点で、実機で測った点ではない。
- **実機で記録された判断にラベルを付けること。** それには Mode A（`replay.py:205-241`）と、
  「ログから `interval_s` を読む」道の両方が要る。**後者は今 無い**（選択肢の枝は `choice_rng` を引く、`replay.py:668-671`）。
  この段はなぞり直し自身の判断点にラベルを付けるところまで。
- **候補のあいだで乱数が完全にそろうこと。** 上の 2 の残りのずれ。
- **ADR 0004 が退けた道を取り戻すこと。** 1 回の判断ごとの契約 bandit と重要度の付け替えは退けられている。

## Acceptance

1. **差し込んだ口が、既存の決まりの答えを変えないこと。** 口を使わない設定で、
   `evidence/18/bound.py` と `evidence/15/onoff.py` が出した主のマスの値を、印字した桁まで再現する。
   違えば何も出さずに止まる（`evidence/19/predict.py` と同じ作り）。
2. **口に渡す状態が、実機の判断の行の欄と 1 つずつ合うこと。**
   `tracker.decision_state`（`src/semindex/tracker.py:264-308`）の欄の名前と、
   実機のログの 1 行（`/home/lab_shared/semindex-eval` の下の `events.jsonl` の `decision` の行）の欄を、
   厳密な突き合わせで確かめる。**シミュレータだけが知る欄が 1 つも混ざっていないこと。**
3. **隣の組ごとの刻みのずれの流れが入ったこと。** 1 つの判断の間隔だけを変えたとき、
   その隣の組の外の刻みのずれが 1 つも動かないことを確かめる。
4. **重みが 1 つの数として固定されたこと。** 出し方と出た値と、その値で固定 3.695 秒の腕と
   固定 10.043 秒の腕の点が合う桁数を書く。
5. **1 本のラベルが作れること。** 1 本について、判断の回数、腕ごとに正解になった回数、かかった秒数を報告する。
6. **ラベルの安定。** 同じ 1 本を Mode B の通し数を替えて 2 回ラベル付けし、正解が一致した判断の割合を報告する。
   **合否は付けない。** 上の「開いている所」の 1 つめの大きさを、ここで初めて数で見る。
7. **観測できる状態を文字にする道が 1 つ置かれたこと。** 欄の並べ方、数の丸め方、直前 8 回のやり取りの書き方を
   1 つの関数に決め、L と M の両方がそれを呼ぶ形にする。1 件あたりの文字数（中央と最大）を数えて報告する。

結果と台本を入れる `evidence/` の番号は、このチケットを取るときに決める。
20 はチケット 07、21 はチケット 08 が使う。
