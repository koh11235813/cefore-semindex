## Task

なぞり直し（`evidence/13`〜`15`）で確かだと言えた差を 1 つ、実機で照らす。差は「切断の多いマス（p 0.4）で、時間切れのときに状態確認の間隔を最短へ戻す決まりは、戻さない決まりより良い」。
この案は 2026-11-17 に書いた。**コードの変更も run も、利用者がこの案を認めてから始める。**

### 何を足すか

エージェントに、隣ごとに間隔を 1 つ持つ決まりを足す（今ある `state_poll_policy` は、時間切れが続いた回数で引く表で、この決まりは書けない）。

| 決まり | 答えが空 | 新しいものが来た | 時間切れ |
|---|---|---|---|
| T37 | 間隔を 2 倍（上限 10.043 秒） | 3.695 秒に戻す | 変えない |
| T37r | 同じ | 同じ | 3.695 秒に戻す |

- 始まりは 3.695 秒。揺らぎは ±10 % で、今の方針と同じく、送るときに 1 回引いて、次の時刻を決め直すときに使い回す（今の動きのまま）。
- 設定の形（案）: `state_poll_rule: {i_min_s, factor, i_max_s, jitter_frac, on_timeout: "keep" | "reset"}`。`state_poll_policy` や間隔の選択肢とは同時に指定できない。
- 「答えが空」は、答えの `hi` の範囲の番号を、その時点で全部持っていること（evidence/11 の `rx_no_new`、なぞり直しと同じ定義）。飛び飛びの持ちぶん（`extra`）は見ない。`extra` は今までのログで一度も出ていない。
- 読めなかった答え（今は `hi: {}` と記録される）は、間隔を変えない。なぞり直しは空として扱うが、読めなかった答えはログに一度も確認されていないので、差は出ない見込み。

## Acceptance

合否の線。run の前に `evidence/16/spec.md` に写し、後から動かさない。

1. 40 本すべて有効（`evalvalid` の印つき 0）。
2. **差が見えたか**: 得の差（T37r − T37）を、evidence/10 の `s6b3p695` と `s6b10p043` の p 0.4 の実測を結んだ線で出す。seed の取り直し 2000 回の 95 % 区間がまるごと正なら「見えた」。0 をまたげば「見えなかった」。まるごと負なら「逆だった」。
3. **なぞり直しが当たったか**: 2 つの段それぞれで、実測の遅れと状態確認の数が、上の予測の ±6 % に入るか。入らなければ、なぞり直しはこの決まりについて外れたと書く（差が見えたかどうかとは別に報告する）。
4. 今ある方針の動きが変わっていないこと: 方針の試験が 1 つも変わらずに通る。加えて、`s6short` の p 0.4 の seed を 1 つ、新しい版で回し直し、状態確認の数と遅れが元の run と同じ程度であること（切断の予定は同じ、乱数も同じなので、判断の並びが一致するはず。一致しなければ止めて報告する）。
