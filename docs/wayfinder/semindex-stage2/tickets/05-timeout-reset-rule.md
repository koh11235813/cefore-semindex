## Task

この案は 2026-11-17 に書いた。**コードの変更も run も、利用者がこの案を認めてから始める。**

### 何を足すか

エージェントに、隣ごとに間隔を 1 つ持つ決まりを足す（今ある `state_poll_policy` は、時間切れが続いた回数で引く表で、この決まりは書けない）。

| 決まり | 答えが空 | 新しいものが来た | 時間切れ |
|---|---|---|---|
| T37 | 間隔を 2 倍（上限 10.043 秒） | 3.695 秒に戻す | 変えない |
| T37r | 同じ | 同じ | 3.695 秒に戻す |

- 始まりは 3.695 秒。揺らぎは ±10 % で、今の方針と同じく、送るときに 1 回引いて、次の時刻を決め直すときに使い回す（今の動きのまま）。
- 設定の形（案）: `state_poll_rule: {i_min_s, factor, i_max_s, jitter_frac, on_timeout: "keep" | "reset"}`。`state_poll_policy` や間隔の選択肢とは同時に指定できない。
- 「答えが空」は、答えの `hi` の範囲の番号を、その時点で全部持っていること（evidence/11 の `rx_no_new`、なぞり直しと同じ定義）。飛び飛びの持ちぶん（`extra`）は見ない。`extra` は、調べたログでは一度も出ていない（`evidence/13/facts/reply-fetch.md`: 137659 件中 0 件）。
- 読めなかった答えは、新しい決まりでは間隔を変えない。ログでは、読めなかった答えと、中身が空の答えはどちらも `hi: {}` で、見分けられない（`evidence/13/facts/reply-fetch.md` の UNCONFIRMED A）。エージェントの中では見分けがつくので、決まりは読めたかどうかを直接使う。なぞり直しは `hi: {}` を空として扱うので、読めない答えが実際に起きていれば、ここで実機となぞり直しが食い違う。
- **順の入れ替えは、新しい決まりのときだけにする。** 今ある二つの方針は、今と同じく、答えの中身を読む前に決め直す（読めなかった答えも「答えあり」として決め直す、今の動きのまま）。今ある方針について、読めなかった答えの試験を足して、今の動きを固定してから変更に入る。

2. **差が見えたか**: 得の差（T37r − T37）で読む。出し方をここで固定する。
   - 遅れ = 窓の中で作られたレコード全部について、4 ホップ先に保存されるまでの時間の、打ち切りを除いた平均（evidence/10 の `delay` と同じ。今の負荷は t0+71 秒までに作り終えるので、早いレコードだけに絞る必要は無い）。打ち切りの割合は並べて報告する。

   - 得 = 1 − 決まりの遅れ ÷ 線の上で状態確認の数が同じ点の遅れ。決まりの状態確認の数が 2 つの腕の外に出たら、得は出さずにそう書く。

3. **なぞり直しが当たったか**: 2 つの段それぞれで、実測の遅れと状態確認の数が、上の予測の ±6 % に入るか。±6 % は、なぞり直しが今ある決まりで最大 5.9 % ずれたことから置いた。時間切れの一歩を含む決まりについては、照らしたことが無い。だから、外れたときは、差が見えたかどうかの結論を書く前に、時間切れの前後の判断の並びを実機のログとなぞり直しで突き合わせて、どこで食い違ったかを先に報告する。
4. **今ある方針の動きが変わっていないこと**:
   - 今ある方針の試験が、1 つも書き換えずに通る。読めなかった答えの試験（上で足すもの）も通る。
