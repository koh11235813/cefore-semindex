## Task

段 2 用に、計測の生成器（`semindex.evalgen`）と回し手（`semindex.evalrun`）を変える。

- 1 回の生成で k 件のレコードを作れるようにする（map の「負荷」）。同じ `at_s` の予定を k 件並べる。k = 1 なら段 1 と同じ予定になる。属性は件ごとに seed から引き、段 1 と同じく p によらない。
- 間隔の選択肢（チケット 01）を、エージェント設定にそのまま渡せるようにする。与えなければ既定の方針。
- run の名前とグループ名の長さを、p によらずそろえる。段 1 では p = 0 のグループ名が `s1_p0_seedN` で、ほかより 2 文字短く、そのぶん p = 0 の通信量がおよそ 47 B／レコード少なく出た（`evidence/s1-breakdown/`）。段 1 の保存先の名前（`p0/`、`p0.1/` など）は変えない。
- 回し手と集計が、k と間隔の選択肢を run ごとの `meta.json` に残し、集計の `runs.csv` に出す。

## Acceptance

k = 1・選択肢なしの設定で、段 1 と同じ予定とエージェント設定が出ることを試験で確かめる（グループ名の長さの違いを除く）。k = 4 で、同じ `at_s` の予定が 4 件ずつ並び、エージェントがそれを 4 件のレコードにすることを試験で確かめる。p の違う 5 条件で、グループ名の長さが同じになることを確かめる。
