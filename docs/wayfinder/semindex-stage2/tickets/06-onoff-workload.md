## Task

入ったり止まったりする負荷（生成が続く時間と止まる時間が交互に来る負荷。evidence/15 の WO と WV）を実機で回せるようにして、
その負荷の上で固定の間隔の腕と、時間切れで最短へ戻す決まりを測る。
この案は 2026-11-19 に書き、同じ日に利用者が認めた（下の「決まったこと」）。

この一手が何のためにあるかを、先に順に書く。

- **(a) なぞり直しを、照らしたことの無い負荷で、初めて実測と突き合わせる。** evidence/13 がなぞり直しを実測と照らしたのは、
  今の負荷（13 秒から 71 秒まで 2 秒おきに作り続けるもの）だけ。evidence/14 と 15 が負荷を替えて出した数字には、
  照らす実測が 1 つも無い。負荷を替えたなぞり直しが当たるかどうかが分からないままだと、evidence/14・15 の結論は宙に浮いたままになる。
- **(b) 入ったり止まったりする負荷の上での判断のログを残して、後の比べの材料にする。** map の「負荷を替えたなぞり直し」（2026-11-17）は、
  式を越える余地が出るとすれば「過去の到着から次の到着が読める負荷」だと書いた。その形のログは、今は 1 本も無い。
  利用者が 2026-11-19 に置いた次の比べ（gemma4-e2b を蒸留した決定器、ログから学ぶ ML、式の決まりの 3 つを比べる）で、
  学習の側に食わせる材料がこれにあたる。
- **(c) 決まりの順位。これは付かないままで終わると予測している。** 固定の間隔の線に対する上積みは、なぞり直しで数 % しか出ておらず、
  20 seed の区間の幅のはるか下にある。下の「示せないこと」に、幅と必要な seed 数を書いた。

**9 時間の実機の時間は、主に (a) と (b) のために使う。** (c) が付かないまま終わっても、この一手は失敗ではない。
逆に、(c) の順位を知るためだけに回すのであれば、この本数では足りないので回さない。

### 何を足すか

生成器に、レコードを作る時刻の形を選ぶつまみを足す。今の形は既定のまま残す。

| 名前 | 中身 | 1 本のレコード数（p 0.4 でのなぞり直しの実績） |
|---|---|---|
| `w0` | 今のまま。13.0 秒から 2 秒おきに 30 回、1 回につき k 件 | 240（k = 4、seed によらず一定） |
| `wo` | origin ごとに、作る 20 秒と止まる 20 秒を繰り返す。最初の始まりは 13〜33 秒 | 平均 188.6（164〜220） |
| `wv` | 同じだが、作る長さと止まる長さを平均 20 秒の指数分布から引き、4〜60 秒に切る | 平均 193.4（100〜264） |

レコード数は `evidence/15/onoff_cells.csv` の p 0.4 の行（`records`、`records_min`、`records_max`）から取った。
下の「負荷の定め方」で種の文字列から `p` を外すので、**実機で引く時刻は evidence/15 が引いたものと別の引きになり、この幅も引き直しになる。**

負荷の定め方（`evidence/15/onoff.py` の `gen_created` と `_ticks` をそのまま写す。なぞり直しと実機が同じ時刻を作れるよう、
式で決めておく）:

- origin ごとに独立に `random.Random(f"ev19:{name}:{seed}:{origin}")` を 1 本引く。`name` は `WO` または `WV`、
  `origin` は `h0` と `h4`。**種の文字列に `p` は入れない。** evidence/15 は `f"ev15:{name}:{p}:{seed}:{origin}"` を使っていたので、
  実機が引く時刻の列は evidence/15 の列と別のものになる。
  **だから evidence/15 の得の値（+1.7 %、+4.9 % など）は、この run に対する予測としてはそのまま使えない。
  予測は、実機が実際に使う experiment.json から作成時刻を読んで引き直す**（下の「先に書いておく予測」）。
  `p` を外す取り分は、`_derive_seed` が 2026-10-23 の指摘で `p` を落とした形（同じ seed なら p が違ってもレコードの引きは同じ）が
  どの負荷でも保たれることと、この負荷で後から p を振るときに、切断以外の違いが混ざらないこと。
- 最初の ON の始まりは `rng.uniform(13.0, 33.0)` 秒。
- `wo` は ON 20 秒・OFF 20 秒を交互に、`wv` は ON と OFF の長さを順に
  `min(max(rng.expovariate(1/20.0), 4.0), 60.0)` 秒で引いて交互に。ON が先。
- ON の塊 `[b, b+L)` は半開区間。`b, b+2, b+4, ...` のうち `b+L` 未満の時刻に刻みを置く。ON が終わる瞬間は刻みではない。
- 110.0 秒を超える刻みは落とし、そこで生成を止める。
- 1 つの刻みに k 件（本番は 4 件）を並べる。今の負荷と同じ、`at_s` を共有する並びにする。
- `at_s` は小数第 3 位（ミリ秒）に丸める。なぞり直しは作成時刻を整数ミリ秒に丸めているので、丸めておかないと
  なぞり直しが回す時刻と実機が仕込む時刻がミリ秒以下でずれる。
- 属性（zone・disaster・media）は、今と同じ `_rng_for(seed, f"records:h{host}")` から、予定の順に 1 件ずつ引く。
  **時刻の乱数と属性の乱数を同じ流れにしない。** 同じにすると `w0` の引く順が動き、既定の負荷が今までと別の run になる。

3. **固定の間隔の線に対する得**。出し方をここで固定する。
   - 見出しの遅れ = **予定された作成時刻が t0+72 秒までのレコード**について、4 ホップ先に保存されるまでの時間の、
     打ち切りを除いた平均。evidence/15 の見出しと同じ区切り。
     選び方は `discovery.csv` の `(origin, seq)` から experiment.json の `schedule[host][seq-1]["at_s"] <= 72.0` を引く。
     実際の作成時刻は予定より中央で 91 ms 遅れるので、境目で選ぶレコードが変わらないよう、予定の時刻で選ぶ。
     これで、なぞり直しが採点するレコードと実機で採点するレコードが同じ集合になる。
     全部のレコードでの値も並べて報告する。
   - **打ち切りの割合（`c4/(n4+c4)`）を、どの遅れの隣にも並べて報告する。** 見出しのレコード集合での割合と、
     全部のレコードでの割合の両方を、10 段それぞれについて出す。線の疎な端だけが別のレコード集合で測られるので、
     割合を見ないと、得が速さの差なのか脱落の差なのかを見分けられない。
     なぞり直しの p 0.4 での割合は、見出しで WO が 3.695 腕 0.0 %・6.0 腕 0.2 %・10.043 腕 3.3 %・T37 3.3 %・T37r 0.03 %、
     WV が 0.0 %・0.0 %・5.0 %・0.2 %・0.0 %。全部のレコードだと WO の 10.043 腕が 24.2 %、WV の 10.043 腕が 27.1 % まで上がる。
     この差が、見出しを早いレコードに限る理由。
   - 状態確認の数は窓ぜんぶ（`[t0+10 秒, t0+130 秒]`）で数える。
   - 線 = 同じ負荷・同じ p の 3 つの腕（3.695、6.0、10.043 秒）の実測を、状態確認の数を横軸、遅れを縦軸にして、
     両対数で結んだ折れ線。決まりの状態確認の数が腕の外に出たら、得は出さずにそう書く。
   - 得 = 1 − 決まりの遅れ ÷ 線の上で状態確認の数が同じ点の遅れ。
   - 区間 = seed 1〜20 を 2000 回取り直す（`default_rng(20261117)`）。取り直しごとに、
     その負荷の 5 段を同じ seed の組で数え直す。
   - まるごと正なら「見えた」、0 をまたげば「見えなかった」、まるごと負なら「逆だった」。
   - **読みは (負荷, 決まり) の 4 行を 1 行ずつ別に付ける。** 4 行が揃うことは求めない。
     なぞり直しの予測（`evidence/15/onoff_gain.csv` の p 0.4、見出しの採点。全部のレコードでの値を括弧に並べる）と、
     結末ごとの主張は次のとおり。

   | 負荷 | 決まり | なぞり直しの得と 95 % 区間 | 予測する読み |
   |---|---|---|---|
   | WO | T37 | -13.8 %、-22.7〜-5.4（全部: -9.6 %、-17.0〜-2.7） | 逆だった |
   | WV | T37 | -8.6 %、-17.8〜-0.3（全部: -3.9 %、-11.3〜+3.3） | 逆だった |
   | WO | T37r | +1.7 %、-5.5〜+8.3（全部: +1.9 %、-3.7〜+7.3） | 見えなかった |
   | WV | T37r | +4.9 %、-2.5〜+11.2（全部: +6.5 %、-0.5〜+12.3） | 見えなかった |

   - **T37 の 2 行**（予測は「逆だった」）: 「逆だった」と出たら予測どおりで、この負荷では T37 が固定の間隔に負けると言える。
     「見えなかった」と出たら、W0 の実機（evidence/16 の -6.4 %、区間 -14.4〜+1.8）と同じ形で、決まりについては何も言えない。
     「見えた」と出たら予測と向きが逆なので、理由を調べてから他の線の結論を書く。
   - **T37r の 2 行**（予測は「見えなかった」）: 「見えなかった」と出たら予測どおりで、**そう出ても決まりについては何も言えない。**
     上積みが無いことを示したことにはならない。区間の幅が効きより広いので、どちらとも言えないという意味にとどまる。
     「見えた」と出たら、なぞり直しの予測より大きい効きが出たことになるので、理由を調べる。
     「逆だった」と出たら予測と向きが逆なので、同じく理由を調べる。
   - WV・T37 の行は、見出しの採点と全部のレコードの採点で、なぞり直しの時点ですでに読みが分かれている（まるごと負と、0 をまたぐ）。
     この行については、どちらの採点でどう出たかを両方書く。
4. **T37r と T37 の直の比べ**（固定の間隔の線を通さない）。負荷ごとに、遅れの比と状態確認の数の比を、
   同じ取り直しで区間つきで出す。遅れの隣には打ち切りの割合も並べる。
   evidence/16 は今の負荷で -23.0 % と +26.8 %、どちらも区間が 0 をまたがなかった。
   読み: 2 つの負荷それぞれで、2 つの比の区間が 0 をまたぐかどうかを書く。**合否は付けない。**
   効きの向きはなぞり直しで分かっているので、ここは測りとして出す。
   区間の幅がどれくらいになるかは `predict.txt` の半幅で先に書いておき、実測の幅と並べて報告する。
5. **なぞり直しが当たったか**。10 段それぞれの**見出しの遅れ**（線 3 の、予定が t0+72 秒までのレコードでの遅れ）と
   **窓ぜんぶの状態確認の数**、合わせて **20 の値**が、予測の ±6 % に入るか。
   `predict.py` はこの 2 つの量と、各段の打ち切りの割合をそのまま出す。
   **20 のうち 18 以上なら「当たった」、15〜17 なら「まちまち」、14 以下なら「外れた」。**
   - 「まちまち」は、入らなかった値がどの段のどの量かを 1 つずつ報告し、その段について下の突き合わせを回す、という意味。
     なぞり直しをこの負荷で使えるかどうかは、そこまでやってから書く。
   - ±6 % は、なぞり直しが今の負荷で実測から最大 5.9 % ずれたことから置いた幅（evidence/13）。
     **この幅は今の負荷で測ったもので、入ったり止まったりする負荷に正しい幅かどうかは分かっていない。**
     だから、外れた値が 1 つでもあれば、どの段のどの量かを、入らなかった度合いと向きとともに必ず報告する。
   - 「外れた」になったら、evidence/16 と同じ手順を踏む。時間切れと ON・OFF の切り替わりの前後の判断の並びを、
     実機のログとなぞり直しで突き合わせ、どこで食い違ったかを先に報告してから、ほかの線の結論を書く。
   - **この線は、生成された時刻が WO・WV の定めどおりであることを示さない。**
     予測は実機の experiment.json から作成時刻を読んで回すので、刻みを並べる新しいコードに間違いがあれば、
     同じ間違いが予測にも入る。ファイルの突き合わせが言えるのは「2 つが同じ時刻を回した」までで、
     その時刻が定めどおりかどうかは別の話になる。
     定めどおりかを示すのは `tests/test_evalgen.py` の刻みの形の試験で、その試験は生成器の出力どうしを比べず、
     手で書いた期待値（刻みの位置、半開区間、110 秒の切り、1 刻み k 件）と突き合わせる。
   - この線が「当たった」なら、evidence/14 と 15 の負荷を替えた数字に、初めて裏付けが付く。
     これがこの一手のいちばんの取り分。

結果は `evidence/19/` に、台本と数字と一緒に入れる（17 は seed を増やす run、18 はなぞり直しで上限を出す段が使う）。map に決定として書く。

### やらないこと

- p 0.2、p 0.5、p 0.6、p 0。切断の無いマスでは 3 つの決まりが同じ数字になるので、決まりの比べには要らない。
- 上限に延ばす形（T37b）。なぞり直しで 0/6 だった。
- 7 つの腕を全部回すこと。腕 1 つにつき負荷ごとに 20 本（53 分）かかる。3 つに絞る。
- `w0` の 6.0 秒の腕。evidence/17 の `s8b6p0` が測っている。
- 学習の方針（蒸留した LLM、ログから学ぶ ML）そのもの。この一手は、その比べに使う負荷と材料を作るところまで。
- probe の数字を読むこと。負荷が変われば probe の種別の混ざり方も変わるが、この一手は読まない。
