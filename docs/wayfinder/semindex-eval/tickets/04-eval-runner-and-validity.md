## Task

計測の回し手と、run の有効性の確認スクリプト。

- 回し手: 条件と seed の一覧を受け取り、1 回ずつ生成・実行・保存する。保存先は `/home/lab_shared/semindex-eval/<段>/p<切断率>/<seed>/`。残すのは `results.json`、各ノードの `events.jsonl`、生成した YAML とエージェント設定。`node_dirs` の残りは run ごとに消す。終わった run は飛ばすので、止まっても続きから再開できる。root で動かすのはオーケストレータ。
- 確認スクリプト: run ごとに前提を確かめ、有効か、印つきかを判定する。確かめるのは、全エージェントの起動と `counters` 行、put の成功、予定どおりのレコード生成、生成した切断の予定どおりのリンクのイベント。全体の収束は判定に使わない。

## Acceptance

確認スクリプトは、前提が崩れた run をそれぞれ正しく印つきにすることを、作った反例で確かめる（判定は完全一致）。回し手は、途中で止めて再開したときに、終わった run を飛ばし、壊れかけの run をやり直す。実機で p = 0.2 を seed 3 個だけ回して、保存先の中身と確認の結果を Resolution に記録する。

## Resolution (2026-10-23)

- 回し手 `semindex.evalrun` と確認スクリプト `semindex.evalvalid` を実装し、統合ブランチに入れた。
- 確認スクリプトが前提の崩れた run を正しく印つきにすることを、作った反例で確かめた（完全一致）。回し手は `DONE` のある run を飛ばし、`DONE` の無い run をやり直す。
- レコードの予定からのずれの許容は 1.5 秒にした。0.5 秒では健全な run の 533 ms の詰まりを印つきにし、2.0 秒ではレコードの間隔と同じで、1 区切りずれても見逃すため。
- root で書き込むので、保存先とそこまでのディレクトリの持ち主と権限を確かめ、満たさなければ run を始めない。ファイルは書いた時点で 0644 にする。semindex の木に未コミットの変更があれば、`--allow-dirty` がない限り始めない。run ごとに `meta.json` に両リポジトリのコミットと有効性を残す。
- 実機で p = 0.2 を seed 3 個回した（保存先の `trial/p0.2/{1,2,3}`）。3 回とも有効。`agent_start` の t0 と scheduler の t0 の差は 9〜11 ms、窓の長さは 120 ± 0.05 秒、リンクのイベントの遅れは 30 ms 以下。
